# Core Memory model v1

Date: 2026-10-01. Authority: Architecture v0.3 §6 and ADR-002/003/006. Scope: A1.1 pure Memory models and explicit review; no Vault persistence, personal migration, Session orchestration, retrieval engine or provider.

The [closed JSON model schemas](../contracts/memory/models-v1.schema.json) and `enouia-memory` describe Fact, Preference, Episode, ProjectState and SessionCheckpoint. Content remains text. ProjectState requires project ID and nonblank state, with decisions/open loops; checkpoint requires session ID, a covered first/last turn and last state, with open loops. Fields belonging to a different kind fail validation. Ordinary records may optionally carry a project ID, unique tags, validity interval, confidence and a `supersedes` link.

IDs consist of a domain prefix (`mem_`, `src_`, `cand_`, `ses_`, `turn_`, `prj_`) followed by 32 lowercase hex digits. `allocate_id` formats 128 bits supplied by an entropy port and propagates failure. The future production Vault adapter must use OS cryptographic entropy; there is no implemented production allocator yet. ID collisions fail insertion rather than overwriting a record. IDs contain no title, path, timestamp or content.

Timestamps use real Gregorian dates, years 0001–9999, exact UTC milliseconds and `Z`. Creation cannot exceed update/review time; source creation cannot exceed memory creation. There is no silent clock repair. Confidence must be finite within 0–1; validity end cannot precede start. JSON shape checks do not replace Rust calendar, graph, provenance or lifecycle validation. Optional fields normalize to explicit null/empty arrays on serialization; semantic round trips preserve all model fields, without promising identical original JSON bytes.

Each memory resolves to a source registry record. Explicit Inspector saves use `manual_save`; explicit remember requests use `explicit_remember`. Conversation sources name session/turn IDs; imports name an importer version and raw SHA-256. Raw source storage and immutability enforcement belong to A1.2. Full turn existence/order checking belongs to the Session model; a well-formed checkpoint ID range alone does not establish that the conversation exists.

`MemoryLedger` is an in-memory validated state machine. Explicit saves require an explicit-action marker and matching source kind. Inferred proposals enter Candidate Inbox and reserve their proposed memory ID. Pending/rejected candidates are never returned by `active_memories`. Approval may edit content and other proposal fields while preserving memory ID, kind, source ID and creation time; the original proposal and review decision remain separate. Rejection preserves the proposal with a nonblank reason. A reviewed candidate cannot be reviewed again, and a failed operation leaves the complete prior state unchanged. The port records a caller's explicit review action; the future UI/IPC adapter must enforce the actual user interaction.

Supersession inserts a new active record, marks the previous active record superseded, preserves its content/source/creation time, and rejects dangling or cyclic links. A stale replacement fails. Undo is allowed only for a current active successor whose predecessor remains superseded: it restores that predecessor and archives the successor while retaining both meanings and the historical link. Neither operation deletes records. Durable audit events, interrupted filesystem transactions and index repair remain A1.2 work; these in-memory checks establish no storage durability.

The snapshot DTO is versioned model interchange, not the frozen on-disk Vault directory layout. Sources, memories and candidates remain distinct. Its validated constructor rejects duplicate IDs, unresolved provenance, forged candidate approval and active supersession conflicts. Consumers must construct through this validation boundary before retrieval; merely deserializing a DTO is insufficient.

The crate depends on serde only in production. It has no Activity, network, filesystem, database, provider or private-credential dependency. [Session v1](SESSION_MODELS_v1.md) validates turn/checkpoint linkage over a complete synthetic bundle. [Core IPC](CORE_IPC_v1.md) and [Capsule/token policy](CONTEXT_CAPSULE_v1.md) have pure contracts; their actual handlers and the Vault/index implementation remain unfinished.
