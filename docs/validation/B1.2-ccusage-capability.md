# B1.2 pinned ccusage capability on synthetic transcripts

Date: 2026-10-01. Runtime baseline: `43982cb`. The [recorded probe](B1.2/ccusage-capability.json) has 16 passing checks with the actual installed `ccusage@20.0.20` wrapper/native binary, Node 24.15.0, and actual Runtime release runner. Only newly created synthetic transcripts were read. This resolves the extended **store** path question raised by the [subprocess handback](B4-subprocess-handback.md); it does not accept personal store inventory or complete operational O3.

The [optional probe](../../scripts/probe-ccusage-capability.mjs) requires an explicitly selected installed `node_modules` root, release runner, and new report path. It copies exactly four public package files (wrapper/package metadata plus the Windows-x64 native executable/metadata) into a temporary independent tool directory. It validates both package names/versions and the pinned optional dependency, records hashes, and confirms the source package is unchanged. It neither installs dependencies nor copies a Moriium collector, config, transcript, credential, or cache data file. The production build/tests/package have no dependency on this selected directory.

The pinned [Node wrapper](https://github.com/ccusage/ccusage/blob/v20.0.20/apps/ccusage/src/cli.js) resolves an optional platform-native executable and passes arguments/environment through. Its [native Claude path reader](https://github.com/ccusage/ccusage/blob/v20.0.20/rust/adapters/claude/src/paths.rs) uses `CLAUDE_CONFIG_DIR` and checks each projects directory. Unlike the generated fake ccusage used in the initial handback diagnostics, the real native tool handles canonical Windows extended store paths. Ordinary and extended paths produce identical normal-store JSON rows in the probe. Node's main-module resolver still rejects extended **script** paths on this host; the selected wrapper path is an ordinary absolute path.

Two synthetic stores contain four assistant records with separate IDs. The normal store has 26 tokens on 2026-09-25 and an explicit zero on 2026-09-26; the Cowork store has 14 and 1. Cache-read/cache-creation/input/output contributions are all counted. Records after 16:00 UTC land on the following Shanghai day. Direct real-package invocations confirm `date` rows and totals 26/15. Transcript sentinel fields and work paths are absent from JSON output.

The copied Runtime runner imports an explicitly unused synthetic zero-sequence identity into an existing empty data root, resumes, discovers normal and transcript-backed Cowork stores, and invokes the real wrapper/native package through its bounded Windows process adapter. The resulting pending batch contains exactly 40 and 1 tokens with `tokens`/`Asia/Shanghai`, successful Claude attemptedAt/succeededAt/updatedAt agreement, and failed/null unconfigured GitHub/Codex sources. Delivery is disabled: exit 4 denotes an unsent pending batch, not successful publication. The runner is paused again before exporting that pending for assertions. No SSH, public HTTP endpoint, scheduler or production state is involved.

Child environments include only Windows process prerequisites and the synthetic HOME/profile/roaming/local/XDG configuration locations. Reports contain normalized synthetic results, package/transcript/binary/harness hashes, versions, outcomes, check names and explicit limitations. No raw process output, absolute work path, personal transcript, token or credential is committed. Temporary package copies and synthetic state are removed after checked containment validation.
