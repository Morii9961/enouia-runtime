# UI v2 · 浏览器语言切换证据补正，2026-11-02

## 发现与原因

复核 Vault 说明时，驱动以 `/src/i18n/index.ts` 动态导入翻译函数，却找不到页面可见的中文导航。隔离页面诊断记录表明，同一页面先加载 `index.ts?t=…`，驱动随后又加载不带查询参数的 `index.ts`；后者语言值为 zh-Hans、字典尚未加载，返回英文，页面则显示中文。原始输出保存在本机 `.design/native-import-recovery-copy-2026-11-02/browser-diagnostic.log`。

根因是 Vite 热更新后模块 URL 不同，驱动创建了另一份模块实例。原驱动只检查 `html lang`，不足以证明 React 页面确实完成了语言切换，因此此前该条件下的焦点断言证据不充分。初始 `?lang=` 截图与直接导入同一模块的 DOM 场景不受这个驱动问题影响。

## 修正与重跑

驱动从当前页面的 resource entries 取得实际已加载的 i18n 模块 URL，复用该实例。切换后同时等待 `html lang` 与真实主导航的中日译文，再检查原节点/实际焦点；JSON 新增 `visibleLanguageChanged: true`。没有修改产品语言存储或新增产品 API。

在本轮当前工作区重跑：

| 浏览器场景 | 组合 | 真实可见语言变化 | 原节点/焦点 |

| Memory 日期标题 | 12 | 12/12 | 12/12 |
| Memory 行元数据 | 12 | 12/12 | 12/12 |
| Provider 设置（3种配置状态） | 18 | 18/18 | 18/18 |
| 新增 Vault 说明区 | 12 | 12/12 | 12/12 |

54组全部通过原有布局边界；Vault12组与Provider18组另外核实虚构水印可见。各目录的 `capture.mjs`、PNG 和 `visual-results.json` 已按上述条件重生成，目录日期保持原切片名称。受影响的旧验证页链接到本记录，不将旧的不足条件继续作为独立语言/焦点证据。

这是隔离无头 Chrome 与虚构 IPC 的浏览器验证，不是 Windows 原生 WebView2、个人数据、真实 Provider 或 owner 验收。未因驱动修正重复运行产品测试；导入/Vault 文案自身的完整前端检查另见对应记录。
