# Activity package-choice reply boundary

Date: 2026-10-09. Scope: the existing native activity_setup command's frontend boundary, separate from Activity IPC v1. B4/J1 remain partial; B5 inactive.

The client previously cast every setup response to Setup without validation. Two regressions reproduce malformed replies reaching callers and inherited constructor text resolving to an Object function: 51/53 frontend tests before the fix, 53/53 after. The client now accepts only the host's action-specific status, selection/refusal/cancellation and clear records. Mode must be sandbox or production; task names follow the host's existing Enouia-Activity- prefix and 1–80 ASCII suffix rule; folder remains a nullable leaf name. Extra fields, path separators, malformed saved/cancelled values and replies for a different action become a nonretryable contract_invalid failure. Refusal text uses own dictionary entries only. Production selection, null/Unicode folder names, suffix boundaries and saved false remain supported.

The [native baseline](Activity-unified/setup-contract-before.json) passes 16/33, with seventeen failures across modeled malformed status replies. The [final native run](Activity-unified/setup-contract-after.json) passes 34/34: nine modeled status cases display the fixed contract failure, make no producer request and show no private marker. Normal selection, native dialog cancellation, real status restoration, clearing and reselection use the actual native command and synthetic installed package. The final run adds one actual-dialog cancellation assertion beyond the baseline's 33 checks. Producer mutation interception is proved before page actions; the complete Activity tree remains unchanged. No Vault is created in this mode.

A [separate actual-operation rerun](Activity-unified/setup-contract-actions.json) on a fresh synthetic package/Vault passes 35/35, including real run/status, pause/resume, healthy pinned-Core rebuild, preserved Memory queries after Activity failure and exact pending across owned-shell termination/restart. [Hashed proof](Activity-unified/setup-contract-proof.json) binds raw reports, binary/helper identities and scope. This does not validate malformed replies from a real account or authorize production operation.

Fresh verification: 53 frontend tests, strict TypeScript/frontend build, embedded desktop and unsigned NSIS build, 26 source/rendered installer ownership checks, Memory/domain guards with 8/7 negative checks, harness syntax, whitespace and evidence integrity 38 reports / 513 selectors / 40 negative checks. The unchanged Rust host/Core, lockfile and pin reuse 32+3 tests and fmt/clippy evidence; the unchanged root producer reuses 223 tests and release evidence. Compilation completed normally in 1m40s. The installer is built, not installed, signed or published.

Build identities are recorded in the proof. No personal Vault/archive, existing/production task, credentials, public upload, server or Moriium source is changed. Actual logon/power, remaining storage phases, sustained stress and real seed/cutover/observed production publication remain separate gates.
