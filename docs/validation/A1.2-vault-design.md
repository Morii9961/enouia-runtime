## Local consistency review

Read the existing Memory ledger/snapshot/source/candidate contracts, Session complete-bundle validation, Core IPC commit response boundary and Activity writer's staged-generation pattern. Verified the design keeps pending proposals outside canonical retrieval, preserves original candidate/source/Session meanings, commits checkpoint events with their canonical records and does not treat SQLite as provenance authority. Existing canonical schema v1 remains unchanged; persistence IDs and file tables are a distinct future storage contract.

Compared the new decisions to ADR-001/002/003/006/014 and Architecture §5/6/14. The new layout applies only to Core after ADR-020 adapter gates; Activity layout/sequence/pending ownership and public schemas are unaffected. The initial full-copy policy intentionally retains history and refuses oversized data; later pruning and idempotency APIs require separate contracts.
