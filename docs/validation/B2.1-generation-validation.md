# B2.1 Pure Activity generation validation

Date: 2026-09-27. Scope: validate one already pinned immutable generation in memory before a future disk reader or uploader uses it. The local manifest v1 names a `g-` generation ID and SHA-256 for `activity.json`, `sequence.json`, optional `pending.json`, and `delivery.json`. All four supplied byte streams must match the manifest; an absent pending file must match manifest `null`. Unknown manifest fields or a different expected generation ID fail. The validator does not scan or select an older generation after a mismatch.

After hashes match, the archive must equal the ActivityData v1 canonical public-byte serialization. The sequence file must be exactly `{"sequence":N}` plus LF, with `N` in the JavaScript safe range. Zero is allowed only with an empty three-source archive and no pending batch; remote unused-identity proof remains a separate provisioning gate. Exact pending bytes are retained and checked with the existing imported-pending contract. Its sequence may be below, but never above, the highest reserved sequence. The current archive must contain every pending date, have source times at least as new, and match any pending snapshot with the same success time exactly. This allows reviewed later corrections without treating an unrelated older archive as the pending batch's state. Pending bytes over the receiver's 4 MiB cap fail. `delivery.json` is hashed and must be a JSON object; its operational schema is still pending.

Six synthetic tests cover a complete image, hash mismatches in all files, missing pending, generation-ID mismatch/path-like IDs, high-water gaps and regressions, archive loss/value substitution, private or inconsistent pending fields, malformed delivery, and zero bootstrap. The image/manifest functions perform no disk I/O and do not claim crash-safe commits, path restrictions, or recovery. The next B2 step must pin `CURRENT`, read only that generation, implement stage/flush/atomic switch on Windows, and fault-test the boundaries.

Checks: `cargo fmt --all -- --check`, `cargo test --workspace` (81 tests, including six generation tests), `cargo clippy --workspace --all-targets -- -D warnings`, and `git diff --check` passed offline with the installed Rust 1.98.1 GNU toolchain. No Activity archive, scheduler, upload, Memory/Context state, or Moriium checkout was changed.
