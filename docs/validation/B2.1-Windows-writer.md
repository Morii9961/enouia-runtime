# B2.1 Windows Activity generation commit

Date: 2026-09-27. Scope: one local generation commit under the live `sync.lock` handle. The writer validates the currently selected generation and expected ID, validates the new complete image, and enforces monotonic source date sets and success times. A new pending batch reserves exactly one next sequence and its data must equal the new archive. While pending is unresolved, subsequent commits keep its exact bytes, sequence, and archive. Pending clear remains disabled until the acknowledgment and reconciliation state machine exists.

The writer creates a new staging directory under the same `generations` parent, writes and `sync_all`s each file, then renames the complete directory to a unique immutable generation name. It writes and flushes a separate `CURRENT.<id>.tmp` before switching `CURRENT` with `MoveFileExW` using `MOVEFILE_REPLACE_EXISTING | MOVEFILE_WRITE_THROUGH` and no cross-volume-copy flag. It reads the selected generation again after the switch. An interrupted stage is left for later recovery; no old generation is deleted. If a failure occurs after pointer switch, the caller must re-read `CURRENT` to determine the result.

[Microsoft's `MoveFileExW` documentation](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) defines replacement and write-through flags; [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers) describes flushing an open file. The local tests establish observed old-or-new visibility at injected process interruption points. These API descriptions and tests do **not** establish power-loss durability of directory metadata or the pointer on every supported filesystem. Root allowlisting, hostile concurrent path replacement, power-loss testing, delivery-state schema/acknowledgment, and controlled migration bootstrap remain required before activation.

Five Windows tests cover a complete delivery-only commit, stale expected ID, fault injection after every staged file flush and before/after the pointer switch, a new pending batch and sequence reservation, and rejection of skipped sequence, pending clear, or pending-byte replacement. They run on synthetic temporary roots and do not touch the production archive or scheduler.

Checks: `cargo fmt --all -- --check`, `cargo test --workspace` (90 tests, including five writer tests), `cargo clippy --workspace --all-targets -- -D warnings`, and `git diff --check` passed offline with the installed Rust 1.98.1 GNU toolchain. No production Activity archive, scheduler, upload, Memory/Context state, or Moriium checkout was changed.
