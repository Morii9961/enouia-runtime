# B1.2 Windows Cowork store discovery

Date: 2026-09-27. Scope: discover a bounded, complete Windows inventory of the normal Claude configuration directory plus local Cowork task `.claude` stores. The caller supplies explicit normal, roaming Claude, and local Packages roots; the function does not infer a Moriium path or read a transcript body. It scans both `local-agent-mode-sessions` and `claude-code-sessions` under roaming Claude data and matching `Claude_*` Microsoft Store package redirects.

Only task `.claude/projects/<project>/*.jsonl` stores with at least one openable transcript are included. Canonical paths are deduplicated, including overlap with the normal store. Traversal stops at `.claude`, so transcript trees are not recursively searched. Optional roots may be absent. An existing unreadable or malformed root, reparse entry, unreadable transcript, depth beyond six, or a previously expected store missing from the new inventory fails discovery instead of silently shrinking the Claude source. Structured errors include no path or transcript content. The normal store is first; discovered stores follow in deterministic order.

Five synthetic filesystem tests cover both store names, Microsoft Store redirect, absent optional roots, normal-store overlap, missing expected inventory, malformed root, excessive depth, empty tasks, and unrelated package names. All created files are fixture data in ignored `target/`; the tests do not scan the user's actual Claude profile.

The older Moriium `cowork.ts` was inspected read-only for the historical directory names and baseline depth. Its directory-read fallback can hide access errors; the Runtime implementation deliberately fails incomplete reads, as Architecture v0.3 requires. Microsoft's [file attribute reference](https://learn.microsoft.com/en-us/windows/win32/fileio/file-attribute-constants) identifies reparse points with `0x00000400`; Rust's [Windows metadata API](https://doc.rust-lang.org/std/os/windows/fs/trait.MetadataExt.html) exposes those attributes.
