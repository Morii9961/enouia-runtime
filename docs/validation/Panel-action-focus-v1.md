The Import and Vault & recovery actions disable their own button while they run: Choose file…, Refresh import list, Start import, Resume, Rebuild index, Verify Vault, Back up to an empty folder…, Preview a restore… and Lock Vault. In WebView2 a focused control that becomes disabled loses focus to the document, as observed natively in the [keyboard journey](Keyboard-journey-v1.md). Start import also removes its preview card. None of these actions restored focus, so a keyboard reader was left on the document after a preview, a list refresh, a started import or a Vault action. No earlier report or fixture covered focus here.

The new 7-assertion `panel-action-focus` journey opens the actual Import and Vault & recovery panels with synthetic picker tokens and IPC. Happy DOM neither blurs a disabled control nor honours `blur()` on one. So while an action is pending, the fixture applies that platform focus fixup itself, exactly as the [session selection](Session-selection-focus-v1.md) journey does, and one assertion checks that it took effect. On the unchanged panels the journey passed **3/7**: focus was lost after a preview, a list refresh, a started import and Verify Vault. Both panels now share a small hook. It records the control that started an action and, once the panel is idle, returns focus to that control, or to the panel heading if the control was removed. It acts only while focus is on the document or that control. Lock Vault hands off to the existing [Vault gate focus](Vault-gate-focus-v1.md), which runs first.
