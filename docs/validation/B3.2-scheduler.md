# B3.2 installation and scheduler packaging

Date: 2026-10-01. Baseline: `e8524e0`. Scope: explicit Windows package preparation, disabled sandbox registration, installed query/uninstall tools, and release execution without a console. Production task registration, delivery activation, personal archives, and login credentials were not changed.

The scripts use only absolute installed config/executable paths and an independent working directory. A new install refuses existing destinations, reparse paths, overlapping data/install roots, invalid/busy/corrupt stores, unpaused state, console binaries, and enabled delivery. Optional tool discovery records selected versions without enabling sources; configured tools must pass bounded hidden version probes. ccusage must be in the selected Runtime-owned tools directory and have pinned package metadata. Collector authentication and ccusage capability remain distinct acceptance gates.

Task definitions use same-user interactive login, least privilege, hourly repetition, 15-minute delayed logon, IgnoreNew, catch-up, battery allowance, no wake-from-sleep, hidden task listing, and a 15-minute overall limit. A release GUI subsystem suppresses console allocation while preserving redirected output. Ownership checks bind task Source marker, action, working directory, and user; hash checks precede registration. Production definitions stay disabled and cannot be registered by this B3.2 tool. Uninstall refuses a running/unowned task and deletes no Activity or installed files.

Packaging tests execute the actual copied release runner against an imported synthetic legacy fixture. They check the release PE subsystem, redirected JSON, configured version probes, output bounds, missing tool rejection, independent installed action, argument/XML escaping with spaces and ampersands, timing/battery/login/overlap settings, default disablement, unchanged data, existing-directory refusal, data overlap, relative path/SYSTEM rejection, production registration refusal, delivery-enabled/unpaused refusal, pause persistence, cross-process file-lock contention, redacted query output, no task overwrite, uninstall preservation/idempotence, and changed-config registration refusal. Scheduler doubles additionally cover running-task and foreign-marker uninstall refusal.

An isolated **real Windows Task Scheduler** test registers a unique disabled sandbox task, verifies disabled registration and query, enables only this test task, then starts it through the scheduler twice: once while Activity is paused and once while another process holds its OS lock. Both complete with result `3`; the matching manual invocation tests additionally inspect `paused`/`busy` JSON states. After uninstall, query confirms the task is absent and exact file-tree hashes prove all synthetic Activity state is retained. Cleanup removes only the uniquely identified test package/data root after ownership checks. No production task or endpoint is involved.

The first actual registration exposed an incompatible UTF-8 declaration on XML passed as a Windows string. Removing the explicit encoding declaration fixed that concrete failure; the corrected definition was accepted and executed by the real scheduler. UTF-8 files remain valid standalone XML. Final ownership/policy-query checks also exposed Windows export omitting default `RunLevel` and `WakeToRun` elements. Readers now accept the effective least-privilege/default policy values; a regression check removes default elements from the scheduler double. Neither Windows behavior was inferred from the doubles.

Checks: PowerShell syntax parsing and packaging checks (42 assertions with scheduler doubles; 41 with the real temporary sandbox task), offline Rust fmt, full workspace tests (160 tests), clippy with warnings denied, release build, and `git diff --check`. The release binary's redirected diagnostics remain valid JSON. The actual temporary task was removed, with no Enouia test task left registered.

Limits: scheduled invocations here are explicit starts through the real scheduler, not observations of an elapsed hourly/logon trigger. Sleep/resume and battery transitions, power-loss durability, selected live Codex authentication, actual Runtime-owned ccusage capability, source totals, isolated receiver publication, and B5 production activation remain unverified. No machine-wide environment changes or automatic task registration were added. Sources/settings and usage are documented in the [scheduler guide](../ACTIVITY_SCHEDULER.md).
