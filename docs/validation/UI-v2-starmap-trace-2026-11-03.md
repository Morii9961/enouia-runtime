# UI v2 #24 完整渲染链路追踪

基线：`4ed0b3d`。本片只给诊断工具加 `--trace` 模式并记录测量，没有改产品绘制。#24 仍未关闭。

```powershell
# 从 apps/desktop 运行
node e2e/starmap-diagnostics.mjs 'C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe' target/starmap-trace --trace
```

## 假设

此前几轮都只看 JS draw 时间与 draw 间隔：球体 JS 约 70 ms，间隔却约 500 ms；聚类 JS 不到 10 ms，间隔约 350 ms。新假设是：间隔里的大部分时间不在渲染进程主线程，而在之后的光栅/GPU 阶段，并且由某类画布指令主导。验证方法是录 CDP 性能追踪，按线程统计顶层事件的忙碌占比；同时统计每次 draw 调用 2D 上下文的次数，并读取浏览器级 `SystemInfo` 的 GPU 特性。

## 结果

环境：自有无头 Edge 156.0.4314.58，1440×900，DPR 1.5，5,000 节点，深色。每组预热 1.2 s 后追踪约 6 s。GPU 特性报告 `2d_canvas`、`gpu_compositing`、`rasterization` 均为 enabled，设备是 NVIDIA GeForce RTX 4080 Laptop GPU，**不是软件光栅**。完整数据见 [JSON](UI-v2-starmap-trace-2026-11-03.json)。

1. **瓶颈在 GPU 进程**。原样绘制时，渲染进程主线程只忙约 10%（球体）/ 3%（聚类），GPU 进程主线程 `CrGpuMain` 忙 66–83%。其中约 5.1–5.7 s 落在 `RasterDecoderImpl::DoRasterCHROMIUM`，几乎全部是 `Deserializing`。
2. **每帧指令量**：约 5,000 个 `beginPath` / `arc`，4,063 个 `fill`，939 个 `stroke`，5,766 组 `moveTo` / `lineTo`，4 次 `setLineDash`；球体另有 4,381 个光晕 `drawImage`，聚类没有。
3. **按组件限定上界**（同一页面、同一轮，原样基线在前后各测一次）：

| 5,000 节点 | 原样 | 合并同样式填充 | 先量化 alpha 再合并 | 跳过星点填充 | 跳过虚线主题线 | 主画布全不画 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 球体 draw 间隔中位 ms | 496 / 512 | 519 | 515 | 511 | **117** | 33 |
| 聚类 draw 间隔中位 ms | 356 / 367 | 390 | 423 | 366 | **80** | 33 |
| 球体每帧 GPU 光栅 ms（约） | 267 | — | — | — | **47** | 0 |
| 聚类每帧 GPU 光栅 ms（约） | 272 | — | — | — | **46** | 0 |

每帧 GPU 光栅 = `DoRasterCHROMIUM` 总时长 ÷ 采样帧数。

## 结论

- 跳过全部星点填充，间隔和 GPU 光栅都不变，星点填充不是主要成本。主画布完全不画时为 33 ms，页面其他部分不是瓶颈。
- **虚线主题连线约占每帧 GPU 光栅成本的 80%**。跳过后球体快约 4.2 倍、聚类快约 4.5 倍。结合[虚线 / 实线对照](UI-v2-starmap-dashes-2026-11-03.md)（实线仍慢于省略），线段数量和虚线效果都有份，成本发生在 GPU 进程的指令反序列化与光栅，而不在 JS。
- 去掉主题线后仍为 117 / 80 ms，剩下的主要是光晕与其他图元，单靠主题线也达不到流畅目标。
- 合并填充的探针**无效**：每颗星的 `globalAlpha` 都含闪烁和深度项，相邻星颜色也不同，原样合并一次都没发生；量化到 1/16 后，实际 fill 也只减少 2–10%。因此不能据此判断合并的收益。要真正合并就得重排绘制次序，这会改变叠加外观。

## 留给 Morii 的取舍

可选方向都会改变外观，需要先确认：主题线降采样或按缩放 / 选择显示，改实线或预渲染到离屏缓存后合成，或按状态重排星点以便合并。没有 Morii 的决定，不改产品绘制。

## 边界

测量环境是无头 Edge，不是 WebView2 实机；draw 间隔不是屏幕呈现时间；每组只有 13–383 次 draw，组间有约 ±10% 漂移。探针模式会改变像素，只用于定位成本。本片只运行了 `node --check` 和诊断本身，没有重跑产品测试或构建，没有读取 Vault 或用户浏览器。
