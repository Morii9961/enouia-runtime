# Activity diagnostic copy feedback lifecycle

Date: 2026-10-10. Baseline: `4375cbde02efea98a7b75bca138ea1db96b6853d`. This changes only the connected React surface's copy feedback and adds a native interaction drill. Activity adapter/producer, IPC, Memory pin and frontend dependencies remain unchanged. J1/B4 remain partial; B5 is inactive.

A delayed clipboard write previously set feedback unconditionally when it settled. Its old success or failure could appear after a refresh or after changing and reselecting a package. Two pending copies could also complete in reverse order, allowing the older request to replace the newer result. A successful refresh kept the previous copy message.

Each copy now captures its request number, read generation and package context. Completion updates feedback only while all three still match. Starting a refresh clears prior feedback; committing refreshed data invalidates a copy started while the read was pending. Existing package replacement and unmount generation/context changes invalidate earlier requests. Current copies still serialize exactly the sanitized overview and show the same success/failure labels. This controls feedback; it does not cancel a system clipboard write already in progress.

The [hashed proof](Activity-copy-lifecycle/proof.json) and [raw native interaction report](Activity-copy-lifecycle/copy.json) record **22/22**, compared with the same complete drill's [15/22 old-build baseline](Activity-copy-lifecycle/before.json). Seven checks demonstrate the old stale-feedback behavior, including a copy begun while actual refresh responses are held before reaching React. Both success and failure completions, reverse completion order, actual clear/picker/reselection and recovery are exercised. Store, package manifest, canonical saved choice and exact three-source histories remain intact. Every clipboard request contains the actual sanitized native overview.

Only the owned WebView's clipboard method is replaced with controlled promises; the real system clipboard is never written. The drill first proves that substitution captured the click. Package setup and Activity reads are actual native IPC. For one interleaving, the forwarding observer holds two responses only after receiving and cloning the actual native replies, then releases them unchanged. There are no modeled IPC replies in this copy drill. The separate polling regression uses explicitly modeled run acceptance/status replies and cannot establish a real run's lifecycle; the separate actual-action/Core regression uses the unchanged real producer and synthetic Vault.

The [first 14/20 baseline](Activity-copy-lifecycle/first-baseline.json) is retained before adding the in-flight refresh interleaving. An [initial 0/1 module-loading failure](Activity-copy-lifecycle/initial.json), caused by importing `realpathSync` from the wrong Node module, is preserved and excluded from acceptance; it preceded app launch and clipboard substitution.

Fresh checks include 58 frontend tests, strict TypeScript/build, native/unsigned NSIS build, 26 installer ownership checks, and Memory/domain guards with 8/7 negatives. The prior [47 host + 3 Core tests](Activity-runner-pipe/tests.json) remain applicable: Rust source, Cargo manifest/lock and the Memory revision are unchanged, and the proof ties the exact host-source digest to that run. The new frozen executable also has separate [polling lifecycle](Activity-copy-lifecycle/polling.json) and [35/35 actual action/Core](Activity-copy-lifecycle/actions.json) regressions.

C17 adds 22 selectors. The offline evidence index is **64 reports / 1,056 selectors / 66 negative checks**, with all 18 rows still partial. This does not establish actual clipboard permission handling, Windows clipboard service behavior, personal-data behavior or production acceptance. No personal Vault/settings, account, credentials, task, live delivery or server was touched; the installer was built, not installed or signed.
