# B2.2 locked offline legacy trio import

Date: 2026-09-30. Baseline: `fc5b4c1`. Scope: bootstrap one paused Activity generation from a reviewed, quiescent copy of legacy `activity.json`, `sequence.json`, and optional `pending.json`. This is a Windows library API; a migration command and production cutover are not implemented here.

The caller holds the Runtime writer lock. The target root must contain only that lock: an existing or corrupt `CURRENT`, generations, bootstrap remnants, or unrelated files block import. Source and target directories must be absolute and disjoint. The bounded legacy inspector validates the copied trio before any generation write; it rejects private extra fields, absent or unsafe sequence state, pending above legacy high-water, and archives inconsistent with pending history. Archive formatting and date order are normalized into canonical public bytes without restamping successful times. The source files remain unchanged and their original archive/sequence hashes are returned separately from the canonical archive hash.

`ImportOptions.reconciled_high_water` is an explicit operator-supplied value covering known local, receiver, and publisher state. It cannot be below the copied legacy high-water or above the JavaScript safe-integer limit. Zero additionally requires `verified_unused_identity` and the generation validator's empty-state constraints. This API does not independently establish remote inventory, select an authoritative archive, resolve conflicting seed values, or authorize upload. A malformed legacy trio is rejected even if a higher proposed high-water could hide its inconsistency.

Pending bytes, original sequence, timestamps, and snapshots remain exact. A separately reviewed archive may contain newer corrections and additional history while pending remains unchanged, subject to the existing generation consistency rules. Import writes `paused: true`, creates no publication receipt, and does not reserve a new batch. Resuming with pending returns its exact original bytes; resuming without pending uses imported high-water plus one. Safe-integer exhaustion blocks new collection.

Bootstrap shares the writer's file-flush, generation-publication, and pointer-switch implementation. Its pointer switch forbids replacement even if an unexpected `CURRENT` appears after preflight. All files and the manifest are flushed before publication; `CURRENT` becomes visible only after the complete generation exists. Failure before the switch leaves no selected generation and preserves remnants for explicit reconciliation. Subsequent imports refuse those remnants rather than resetting sequence state. After a switch error the caller must reread `CURRENT`; a completed import remains paused and readable. These tests establish process-interruption visibility, not power-loss durability or protection against hostile concurrent directory replacement.

Nine synthetic Windows tests cover import/export round trips with a richer archive and formatted pending bytes; source immutability and raw/canonical hashes; skipped high-water; absent pending; pause/resume decisions; existing, corrupt, and interrupted target refusal; missing sequence; unsafe/lower sequence and traversal ID rejection; invalid/private pending; verified zero and sequence exhaustion; disjoint roots; interruption after every flushed file and both publication/pointer boundaries; and no-replace pointer behavior. The existing writer, recovery, publication acknowledgment, and cross-process lock tests also pass after sharing the persistence helper.

Checks passed offline with installed Rust 1.98.1 GNU: `cargo fmt --all -- --check`, `cargo test --workspace` (140 tests), `cargo clippy --workspace --all-targets -- -D warnings`, and `git diff --check`. No personal archive, credential, scheduler, production endpoint, Memory/Context state, or Moriium checkout was used or modified. Real migration inventory/reconciliation, CLI/config wiring, installed execution, isolated receiver acceptance, and power-loss evidence remain separate gates.
