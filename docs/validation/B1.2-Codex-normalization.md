# B1.2 Codex usage-result normalization

Date: 2026-09-27. Scope: strict conversion of an `account/usage/read` result into the existing Codex Activity snapshot. Interactive app-server transport and executable discovery are separate pending B1.2 work.

The normalizer requires a nonempty `dailyUsageBuckets` array with real unique dates and safe nonnegative token integers, plus a safe nonnegative `summary.lifetimeTokens`. It checks the safe sum of **all** returned buckets against lifetime before the B1.1 merge filters dates. The server's date labels remain `Codex`; they are not converted to Shanghai days. Unknown private fields are discarded by the ActivityData allowlist. An absent, null, invalid, or mismatched lifetime fails this source, as Architecture v0.3 deliberately requires even though the legacy importer could accept a missing lifetime.

The synthetic `codex-usage-v1.json` contains unsorted days, explicit zero, and private sentinel fields. Four integration tests cover valid normalization, lifetime failures, invalid/duplicate/unsafe buckets, aggregate overflow, and an archive whose retained total exceeds the current response lifetime. The last case proves lifetime reconciliation applies to the raw response, not the merged archive.

The [official OpenAI Codex App Server documentation](https://learn.chatgpt.com/docs/app-server) describes the `initialize` / `initialized` handshake and `account/usage/read` result with `summary.lifetimeTokens` and `dailyUsageBuckets`. It notes these fields may be null; the Runtime contract intentionally treats that as unavailable rather than zero. The legacy Moriium importer was inspected read-only for compatibility and the documented stricter difference. No token or personal response was read or stored in this feature.
