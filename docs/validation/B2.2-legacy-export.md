# B2.2 locked legacy trio export

Date: 2026-09-28. Scope: read-only export of the current validated Runtime Activity generation into a new, separate legacy-compatible directory. The caller holds the Activity writer lock for the entire operation. The recovery audit blocks export if selected or retained published state is corrupt or ambiguous.

The output contains only `activity.json`, `sequence.json`, and `pending.json` when pending exists. It copies their exact bytes from the selected generation, including skipped high-water sequence values and any frozen pending batch. The returned summary records the generation ID, highest reserved sequence, and SHA-256 for each exported file. Operational `delivery.json`, lock files, credentials, and repository paths are not copied. The destination must be outside the store and absent; each file is flushed in a new sibling staging directory before a same-parent, no-replace rename publishes the bundle. A failed write can leave a partial staging directory for inspection; it never changes Runtime state or an existing destination.

Three Windows tests cover exact pending-byte/high-water preservation, absent pending plus destination refusal, and corruption refusal. The tests use synthetic temporary roots and never touch Moriium or production Activity state.

Checks: `cargo fmt --all -- --check`, `cargo test --workspace` (96 tests), `cargo clippy --workspace --all-targets -- -D warnings`, and `git diff --check` passed offline with installed Rust 1.98.1 GNU. This is an export primitive, not a complete migration converter, backup policy, or permission to activate an old writer. Rollback still requires current remote high-water and pending reconciliation plus old-contract validation.
