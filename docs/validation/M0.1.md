## Independent synthetic oracle

The private-field sentinel input is `tests/fixtures/activity/moriium-oracle-input.json`. At fixed receiver time `2026-09-26T08:00:01.000Z`, the unchanged Moriium `validateBatch` produced normalized public bytes in `moriium-public-data.json`; Moriium's `JSON.stringify(batch.data) + "\n"` and Node SHA-256 yielded `754acd97ebfa4d97fe566779e7dbda0d03a5f6c426194729abc07aa25ac80bc9`. A Rust integration test invokes the actual Rust normalizer/serializer/hasher and checks both committed expectations. The fixture includes unsorted dates, an explicit zero, a failed Codex source retaining an older success time, and private sentinels at every public nesting level.

Compatible verified cases: fixed source literals and units, zero-valued days, null sources, three successes, failed-source retention, derived `succeededAt`, allowlist and ordering, public UTF-8 bytes and SHA-256. The Rust tests also enforce real and unique dates, leap-day handling, JavaScript-safe numeric bounds and sums, valid sequence, exact envelope times, and cross-field timing. `validate_failed_retention` additionally compares each failed source against a supplied prior archive; a single batch alone cannot prove that history was retained.

Known differences and limits:

- Rust rejects a daily sum over `MAX_SAFE_INTEGER`; Moriium's `validateActivity` checks individual day values but does not sum them. This stricter rejection follows Architecture v0.3's safe-arithmetic requirement.
- Rust accepts deterministic ISO public timestamps (date-only or offset-bearing). Moriium's `Date.parse` also accepts some non-ISO strings; those are not covered and are rejected here. Standard producer UTC-millisecond timestamps and offset-bearing ISO examples were tested. An unusual legacy seed requires a separate compatibility check.
- Receiver-valid old timestamps can fail the public manifest's exact-ISO `succeededAt` rule. `validate_publishable_batch` detects that case without changing the retained timestamp.
- Imported pending objects with unknown fields or a claimed `succeededAt` inconsistent with the snapshot are rejected instead of normalized in place; normal new-batch input still strips extras as Moriium does. This preserves retry identity.
- The Schema files describe normalized output and structural constraints. Rust tests, not Schema-only checks, prove real-date, safe-sum, cross-field time, and privacy behavior.
- This is a single synthetic batch oracle, not a full same-input collector/merge comparison or a deployed receiver/publisher acceptance. Those belong to B1/B4. No real archive, task, CLI credential, server, or production state was inspected.
