# Validate requested history before filtering

Date: 2026-10-10. Baseline: `5be43d1e97164839377f1c0a3339aa16631b2146`. This changes only the Activity host's preview-to-days conversion. Producer/store, IPC schema, frontend, dependencies and Memory pin remain unchanged. J1/B4 remain partial and B5 is inactive.

The host previously returned an empty `activity_days` list when the requested preview source was missing or malformed. Invalid records outside the requested range also disappeared before the client could reject them. The derived response therefore looked valid even though its source history was not. Conversion now requires the supported preview/data versions and an explicitly present requested source. Null means no history; otherwise its days must be an array. The entire requested series is checked for exact day fields, real ascending unique dates, nonnegative safe integers and a safe sum before inclusive range filtering.

The [hashed proof](Activity-days-provenance/proof.json) records [49/49 actual native checks](Activity-days-provenance/days.json), against [32/49 on the old executable](Activity-days-provenance/before.json). All 17 baseline failures are refused-history cases: unsupported versions, missing sources, malformed source/array shapes, invalid dates or values, private extra fields, duplicates, descending dates and unsafe totals. The malformed records intentionally lie outside the requested range. A controlled owned runner emits these replies through the real package hash check, bounded process reader and native IPC; browser replies are not substituted.

Positive cases retain an explicit null source, an empty array, inclusive boundary dates, explicit zero, the maximum safe integer and mathematically integral JSON numbers written as `1.0`/`2.0`. Existing structured runner errors pass through unchanged. Only the requested series and its derivation containers are validated here; unrelated snapshot metadata and other sources are not a complete preview-validation claim.

The [53 host + 3 pinned-Core tests](Activity-days-provenance/tests.json) pass. The initial focused baseline reproduced a missing requested source becoming a valid empty list; the old native executable additionally covers every refusal case in the final drill. Separate [27/27 schedule-container checks](Activity-days-provenance/schedule.json) and [35/35 actual producer/Core action checks](Activity-days-provenance/actions.json) pass on the new frozen executable. Original runner/manifest, saved choice and complete Activity store remain exact after recovery.

Fresh fmt/clippy, strict TypeScript/build, unsigned NSIS build, 26 installer ownership checks and Memory/domain guards with 8/7 negatives pass. The unchanged frontend's 63-test evidence is reused with model/client source digests. C17 adds 51 selectors, bringing the index to 71 reports / 1,230 selectors / 78 negative checks. All 18 rows remain partial. No personal data, accounts, scheduled task, live delivery, installation, signing or deployment was involved.
