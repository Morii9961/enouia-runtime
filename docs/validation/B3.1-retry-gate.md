# B3.1 transport retry eligibility

Date: 2026-09-28. Scope: one locked decision before restricted SSH transport. Automatic sends wait until the pending batch's persisted `nextEligibleAtMs`; explicit manual intent may bypass that wait. Pause and the single-writer lock remain effective for both intents. A deferred result carries the next eligible time and launches no process.

The gate audits the selected generation, reads the exact pending bytes and retry record, and checks a nonnegative current clock. Once due, transport still uses stdin-only restricted SSH and returns `TransportCompletedUnverified`; neither a due time nor SSH exit zero acknowledges publication. Public observation uses its separate read-only path while the retry wait is active, so a lost acknowledgment can still be resolved by matching public content. The one-automatic-send-per-invocation rule belongs to the future headless runner.

Synthetic Windows tests cover no process launch before the deadline, manual override with unchanged pending bytes, an automatic send at the deadline, and a paused manual attempt. The existing acknowledgment test observes and clears a pending batch while a future retry time is recorded. No production scheduler, remote receiver, or live public endpoint was exercised.
