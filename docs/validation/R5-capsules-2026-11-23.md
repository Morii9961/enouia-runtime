# R5 B1：保存召回预览为 Capsule（2026-11-23）

[R5 清单](../integration/R5_SURFACE_GAPS_2026-11-23.md)第二类 B1，Memory 先实现、默认不启用，是否在真实库上打开由 Morii 周末决定（[待定事项](../integration/R5_MORII_DECISIONS_2026-11-23.md) D2）。pin 升至 Memory main `3c6e5320a58e6d833873c31828573a271ce56ee6`（[#151](https://github.com/Morii9961/enouia-memory/pull/151)，ADR-MEM-173，审阅 head `4127edb`；aggregate `e699ef6d…`，61 命令）。

## 改动

- 适配器：只读的 `capsules`（`NativeMemoryOwner::capsules`，附本机开关状态）；`capsule_saving`（每个库一份本机开关，存在 Runtime 配置目录的 `capsule-saving.json`，不写库，默认关）；`plan_capsule`（开关关闭时拒绝 `capsule_saving_off`；把预览里的记录编号与修订在原生侧解析成带哈希的引用，再用 `OwnerAction::Capsule` 计划，确认沿用 `confirm_action`）。成员为空即删除。
- 召回与 Context：预览下方出现 Capsule 名称与“保存为 Capsule…”，看计划（条数、同名会替换）后确认写入；右侧“已保存的 Capsule”列出名称、提示、条数、已不可读的条数，可“用这个提示再预览一次”（分数与理由不存，重新跑召回），开关打开时可“删除…”。开关关闭时说明可在设置里打开、之前不会保存。
- Settings：新增“已保存的 Capsule”开关（关 / 开），说明默认关闭、保存会写入库。
