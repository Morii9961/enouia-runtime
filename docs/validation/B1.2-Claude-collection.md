# B1.2 Claude daily-report collection

Date: 2026-09-27. Scope: invoke a configured Node executable and Runtime-owned ccusage CLI once for every supplied Claude configuration store. The command is `claude daily --json --offline --timezone Asia/Shanghai`; each invocation receives only its own process-scoped `CLAUDE_CONFIG_DIR`. The normal Claude store must be included in the caller's inventory. The adapter uses the shared bounded `ProcessRunner` port and passes every complete JSON report to the previously validated Claude normalizer.

Node, CLI, and store paths must be absolute; an empty inventory or exact duplicate is rejected before launching. Canonical/reparse-aware deduplication, transcript-backed Cowork discovery, and expected-store inventory review belong to the next B1.2 discovery feature. Each store has a 120-second process deadline and 4 MiB combined output cap, subject to the later runner's aggregate 10-minute collection budget. A nonzero exit, malformed or oversized output, failed process, or invalid report fails the entire Claude attempt. Cancellation aborts the candidate batch. No partial store sum or raw process text enters public data.

Five fake-runner tests cover exact arguments and scoped environment, complete two-store aggregation, later-store failure, malformed report, nonzero exit, output bounds, invalid/duplicate inventory, and cancellation. The real Windows `ProcessRunner` has [separate process tests](B1.2-Windows-runner.md). The [ccusage source-focused CLI documentation](https://github.com/ccusage/ccusage/blob/main/apps/ccusage/README.md) shows `claude daily`, offline, JSON, and timezone options; the [configuration guide](https://github.com/ccusage/ccusage/blob/main/docs/guide/getting-started.md) documents `CLAUDE_CONFIG_DIR`.
