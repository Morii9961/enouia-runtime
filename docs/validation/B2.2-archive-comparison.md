# B2.2 per-source archive comparison

Date: 2026-09-28. Scope: compare a validated Runtime Activity archive with a validated candidate legacy archive without merging or choosing an authority.

The comparison reports, separately for GitHub, Codex, and Claude, each side's canonical snapshot hash, dates present only on either side, changed values on shared dates, and whether the candidate success time regresses. Loss of current history, changed values, a missing source, or a success-time regression marks that source as requiring reconciliation. Candidate-only dates or a newly present source are visible but do not alone mark a conflict. This rule identifies where an operator choice is needed; it does not declare a candidate authoritative.

Two Windows tests cover all three sources, historical-date loss, new dates, corrected values, missing/new source snapshots, time regression, and malformed comparison time. The full workspace has 102 tests. `cargo fmt --all -- --check`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, and `git diff --check` passed offline with installed Rust 1.98.1 GNU.

The comparison is pure and read-only. A later importer must record the reconciliation choice, validate the chosen archive and exact pending bytes, and enforce local and remote high-water gates before any new upload.
