# B2.2 read-only legacy trio inspection

Date: 2026-09-28. Scope: validate a quiescent copy of the old Activity `activity.json`, `sequence.json`, and optional `pending.json` before any import or reconciliation decision.

The inspector uses bounded Windows reads that reject reparse files. It parses the old archive through ActivityData v1 validation, rejects unknown fields at every public archive level, and prepares canonical public bytes without changing the copied files. It accepts harmless whitespace and day ordering differences. It records SHA-256 hashes of the original archive and sequence files separately from canonical output; it retains exact pending bytes and their hash. Sequence must be one safe integer. The candidate archive, high-water, and pending batch must pass the generation validator, including pending sequence not exceeding high-water and pending history being present in the archive.

Two Windows tests cover a formatted copied trio with sequence 5 and pending sequence 1, exact pending preservation, raw versus canonical hashes, reordered dates, private archive extras, zero sequence with populated archive, and pending beyond high-water. The full workspace has 100 tests. `cargo fmt --all -- --check`, `cargo test --workspace`, `cargo clippy --workspace --all-targets -- -D warnings`, and `git diff --check` passed offline with installed Rust 1.98.1 GNU.

This inspector is read-only. It does not choose a source archive among conflicting copies, establish remote high-water, import into the generation store, activate upload, or prove that a live old producer was quiescent. Those gates remain in the migration runbook.
