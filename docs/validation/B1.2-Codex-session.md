# B1.2 Codex app-server session protocol

Date: 2026-09-27. Scope: Codex `initialize` / `initialized` / `account/usage/read` over a caller-owned, bounded JSON-lines session. This does not launch or discover an executable.

The protocol driver sends an `initialize` request with `enouia_activity` client metadata, waits for the matching response, sends `initialized`, then asks for `account/usage/read`. It ignores unrelated notifications and accepts only the matching response ID. The parsed result goes through the previously validated Codex lifetime reconciler. A `-32600` method error becomes an `unsupported_method` source failure; malformed or incomplete responses fail only Codex. Cancellation aborts the whole candidate run. A 90-second aggregate deadline and 4 MiB cumulative response budget are enforced by the driver; the `JsonLineSession` platform adapter must honor each remaining timeout, byte limit, and cancellation signal.

Seven fake-session tests cover request order, interleaved notification, unsupported method, invalid handshake/result, malformed and oversized lines, cumulative output, session failure, and cancellation. Neither raw response text nor transport errors enter public data.

The [official OpenAI Codex App Server documentation](https://learn.chatgpt.com/docs/app-server) specifies the handshake, JSON-lines stdio transport, and `account/usage/read`. The installed Codex CLI candidate reported `0.158.0-alpha.2.1`; its generated JSON Schema contained the usage method and showed that its request does not require `params`. The schema probe lives only in ignored `target/` files. No account token activity or credential file was read during that probe. A live authenticated request and platform process launch remain separate acceptance work.
