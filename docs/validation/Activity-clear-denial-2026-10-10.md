# Saved-choice clear under hidden existence

Date: 2026-10-10. Baseline: `9f1441dcbd929bf6eea0d8ce86488a43ca0a2554`. This changes the Activity host's saved-choice deletion result. Producer/store, IPC schema, frontend, dependencies and Memory pin remain unchanged. J1/B4 remain partial and B5 is inactive.

The old expression accepted deletion success or a false existence query. Actual Windows access denial can make that query false even while the file remains present. A new owned fixture denies directory listing/read-attributes/delete-child and file read-attributes/delete to the current user. Rust observes `exists() == false` while deletion returns `PermissionDenied` (OS error 5); the old expression then reports success incorrectly. Clear now succeeds only after deletion or an explicit `NotFound` error.

The current window still disconnects when a clear fails. Its existing warning correctly explains that the retained saved choice may reconnect after restart and offers another attempt. This fix changes the saved result rather than the disconnect policy.

The [hashed proof](Activity-clear-denial/proof.json) records [17/17 actual native checks](Activity-clear-denial/denial.json), against [13/17 on the old executable](Activity-clear-denial/before.json). The four baseline failures are the native clear result, reconnect/retry explanation, retained failure status and remount feedback. Replies are observed without replacing native IPC. File/directory descriptors and file bytes restore exactly before recovery. Restart reads the retained choice and its original source histories; a subsequent clear deletes the file successfully and remains forgotten after another restart. The entire Activity store and package manifest remain exact throughout this drill.

The [50 host + 3 pinned-Core tests](Activity-clear-denial/tests.json) include a separate child process under the same actual denial, with the old expression as a negative control. Before the product fix the focused suite had two passes and one failure, while still restoring exact descriptors and bytes. Missing, existing and already-cleared files establish the legitimate success paths. One of the 50 host entries is the child helper, which returns without a fixture when run directly; only its parent and the positive deletion test add unit selectors.

Separate [19/19 file-sharing/remount checks](Activity-clear-denial/sharing.json) and [35/35 actual producer/Core action checks](Activity-clear-denial/actions.json) pass on the new frozen executable. Fresh fmt/clippy, strict TypeScript/build, unsigned NSIS build, 26 installer ownership checks and Memory/domain guards with 8/7 negatives pass. The unchanged frontend's [63-test evidence](Activity-future-age/tests.json) is reused at its exact model-source digest. C17 adds 19 selectors, bringing the index to 69 reports / 1,151 selectors / 76 negative checks. All 18 rows remain partial.

The denial targets only newly created owned temporary fixtures and is released through a bounded helper with exact restoration in `finally`. No personal data, accounts, scheduled task, live delivery, installation, signing or deployment was involved. This establishes the tested Windows denial and recovery; disk-full, power-loss and production acceptance remain open.
