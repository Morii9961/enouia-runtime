# B2.1 published-generation recovery audit

Date: 2026-09-28. Scope: a read-only audit of the Activity store immediately before a generation commit, while the Windows writer lock is held.

The audit reads the selected `CURRENT` generation and validates every other published `g-*` directory using its manifest hashes and content rules. A published generation with a higher reserved sequence blocks the next commit, including when `CURRENT` has been restored to an older pointer. A generation at the same sequence must have the same archive and exact pending bytes; delivery-only differences are allowed. A corrupt published generation or an unknown/reparse entry also blocks writing. The audit does not choose a fallback, remove directories, or rewrite `CURRENT`.

Incomplete `.staging-g-*` directories are counted and left in place. They have not been published by the writer and do not by themselves block the next commit. A fully published directory left before a pointer switch is conservatively treated as potentially selected in the past, because it cannot be distinguished from a rolled-back pointer using local files alone. An operator must reconcile such a directory before writing resumes. This can temporarily block a safe retry, but prevents sequence reuse when the prior state is uncertain.

Three new Windows tests cover pointer rollback after sequence reservation, corruption in an unselected generation, and same-sequence conflict versus an incomplete staging remnant. The existing writer fault-injection tests continue to exercise the pointer-switch boundaries. The test roots are synthetic temporary directories; no production state or scheduler is touched.

Checks: `cargo fmt --all -- --check`, `cargo test --workspace` (93 tests), `cargo clippy --workspace --all-targets -- -D warnings`, and `git diff --check` passed offline with the installed Rust 1.98.1 GNU toolchain. This audit does not prove power-loss durability, resolve an ambiguous published directory automatically, or authorize pending clear or delivery.
