# B2.1 locked Activity run-start decision

Date: 2026-09-28. Scope: the first decision in a locked Activity invocation. It audits the selected and retained published generations before exposing either a retry or a new collection sequence.

If a pending batch exists, the decision returns its exact stored bytes and original batch sequence, even when the reserved high-water is greater. It does not collect or allocate another sequence. With no pending batch, the decision returns the validated archive, current generation ID, and `highestReserved + 1`. Exhaustion of the JavaScript safe-integer sequence range blocks collection. A corrupt or ambiguous store blocks both paths. The caller must retain the writer lock through the remaining run; this function does not send, clear pending, or schedule retries.

Two new Windows tests cover an imported pending batch at sequence 1 with reserved high-water 5, normal next-sequence allocation, sequence exhaustion, and a rolled-back pointer. No production Activity state or external receiver was used.
