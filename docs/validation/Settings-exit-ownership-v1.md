# Settings startup observation and Exit admission

Date: 2026-10-16 (Asia/Shanghai). Baseline `6cb6920eab5ca5a84e23b7d9f55773cf3f61609d`; Memory pin remains `8186aed861af08cf7a2c5d8c912a24eae51b4d66`.

Source inspection found three inconsistent lifecycle views: MemoryBadge's open indicator ignored `companion.exiting`, MemorySettings rendered open details during host change/Exit, and CompanionSettings did not include local/observed Exit in startup-switch admission. The startup read also shared the write action and had no explicit recovery for native string failures. Native `startup.rs` reports supported/enabled plus `disabled`, `enabled` or `different_installation`; command errors are strings, not Memory CallError values. Generic keyed Memory Retry behavior must not be invented for these commands.

The header and Settings now withhold current-open indicators/details during their observed lifecycle states. Local or observed Exit disables the startup switch. Startup reads use the existing latest-read hook and an explicit **Read startup setting again** control. Initial failed reads remain unknown; failed refreshes label and retain the prior setting, withholding changes until a fresh read succeeds. Reads remain available during Exit and issue only `startup_status`. A new switch gesture still submits only the existing boolean `startup_set` argument. Native commands, Registry handling, pin and dependencies are unchanged.

Fresh verification: `npm --prefix apps/desktop test` passed 95 existing frontend tests plus 56 DOM-model component assertions (Settings 17, Home 15, lifecycle 24). TypeScript, strict fixture typing, desktop no-bundle release build, pin guard (eight negatives), dependency guard (seven negatives), JSON/diff checks passed. Unchanged native test/Clippy/format evidence is reused from [the prior verified slices](Home-status-observation-v1.md). Only the exact development dependency `@happy-dom/global-registrator` 21.0.3 and its locked development-only graph were added; production dependencies and native sources remain unchanged.

**DOM interaction verification.** `apps/desktop/e2e/settings-exit-ownership.html` renders the actual MemoryBadge, MemorySettings and status provider with synthetic native string failures, startup observations and Exit. With no available browser connection, `tests/dom-fixtures.mjs` runs the same repository fixtures through Vite's existing TSX loader in isolated Happy DOM worker processes. `npm run test:dom -- --settings-baseline` injects only the original status.tsx from the exact baseline through a read-only Vite loader: 13 baseline assertions ran and seven failed, including the missing read control. Four recovery branches requiring that control were unavailable. Final execution runs all 17 Settings assertions plus the 39 related assertions successfully. [Selected actual DOM results](Settings-exit-ownership-dom.json) preserve this evidence boundary.

The development runner follows the [official Node test-environment setup](https://github.com/capricorn86/happy-dom/wiki/Setup-as-Test-Environment), with installed 21.0.3 types/source checked against Node 24.15.0. It disables DOM script evaluation and external JS/CSS/image loading, imports only three named local fixtures, and runs each in a separate process. Native Node timers are retained because Vite requires `.unref()`; fixtures unmount to clear their polling, the Vite server and DOM resources close, and each process exits naturally. DOM globals remain only until that worker exits so a queued React cleanup cannot see a deleted window. The baseline command checks the exact expected seven failures; ordinary `npm test` requires every final assertion to pass. `--details` prints full actual records. This is not a connected browser, rendering/layout, physical input, Windows/Narrator, or native acceptance result.

No actual login setting, Registry entry, Exit, personal Vault, Provider, Activity producer, installer or manual status snapshot was accessed or changed. Owner files are preserved. `npm audit` also reported the already-locked development-only source-map-js 1.2.1 advisory; its version/integrity are unchanged by adding the DOM runner. No blanket dependency upgrade was performed.
