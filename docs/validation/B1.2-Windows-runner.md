# B1.2 Windows process runner

Date: 2026-09-27. Scope: a Windows implementation of the shared `ProcessRunner` port. It launches a caller-selected absolute executable with a hidden window, pipes only requested stdin, captures stdout and stderr separately, and applies one cumulative output cap. The child is assigned to a private Windows Job Object that terminates descendants when closed. The work directory is the executable's parent, so the runner does not depend on an inherited repository directory.

The runner polls cancellation and a per-request deadline. Output workers drain both streams concurrently, so a full pipe cannot stall the child. An output overflow, timeout, cancellation, or process failure returns a structured component-specific error without placing raw output into an exported error. A nonzero exit is preserved as `ProcessOutput` for the source adapter to classify; stderr remains private to that adapter. Process-local environment entries are supplied through the request without modifying machine configuration. The runner rejects relative executables, zero limits, and capture limits over 64 MiB.

Four real-process tests use the repository's synthetic PowerShell fixture. They check stdin, environment, both streams, nonzero exit, timeout, cancellation, stderr overflow, and invalid bounds. The existing GitHub adapter fake-runner tests continue to check its GraphQL request and source-specific validation. No authenticated GitHub or Codex request is made by the process tests.
