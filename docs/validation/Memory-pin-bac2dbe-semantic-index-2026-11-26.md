## Runtime 的做法

- **新模块 `memory_semantic.rs`**：实现 Memory 定义的 `SemanticIndex`。
  - `query()`：用标准库 TCP 直接向 `127.0.0.1:11434/api/embed` 发 HTTP/1.1 请求，不经过系统代理，不新增依赖。最多等 1.5 秒；Ollama 没装、没运行、超时或出错时返回 `None`，召回退回字面匹配。
  - `memory()`：只查内存缓存，不阻塞。
- **后台补算**：登记库的状态轮询最多每分钟取一次读取器的 `semantic_texts(上限)`，缺的向量交给后台线程，每批 16 条调 Ollama 计算；清单里已经没有的目标（撤回、遗忘、删除）从缓存清掉。
- **缓存位置**：`%APPDATA%\com.enouia.runtime\semantic-bge-m3.json`，和本机 Agent 名称放在一起，不进库、不进导出、不进仓库。
- **挂点**：同一个索引挂在完整历史读取器上（召回预览和 Context），也挂在每个本机 Agent 连接的宿主上。
- **界面**：Settings 显示语义检索状态（检查中、建立索引 n/总数、就绪、本机模型没运行）。召回理由 `semantic` 和关联边 `semantic_neighbor` 显示为“语义相近”。

## 后续：pin `ea3f59f`（ADR-MEM-221，相对阈值）与模型预热

Memory 按上面的分布改成相对阈值（[#214](https://github.com/Morii9961/enouia-memory/pull/214)）：
- 相似度先过绝对下限 500；

- 样本少于 30 个时，退回 550 / 650。

pin 升到 `ea3f59f6e356ad2cb43d2b72d70b99314177ec63`，只改了 `contract` 和 `host`。

第一次复查时，召回里一个“语义”理由都没有。原因在 Runtime：向量已经全部缓存，启动时不需要调 Ollama，模型就没有加载；冷启动约 14 秒，而查询最多等 1.5 秒，所以这组查询全部超时，退回字面匹配。电脑闲置后的头几次召回也会这样。修复：
- 后台补算先发一次预热请求，模型加载好以后状态才报“就绪”；
- 每个请求带 `keep_alive: 30m`。

修复后复查（只读，退出码 0，CURRENT 前后均为 440）：

| 问题类型 | 只用字面匹配 | `ea3f59f` 加语义 |
| --- | --- | --- |
| 我去过某地吗 | 第 1 条无关 | 16KB 前 3 条、64KB 前 5 条都直接相关 |
| 最近在学什么 | 没有相关结果 | 相关记录靠语义单独被找出，排第 1 |
| 喜欢什么画风 | 答案不在结果里 | 答案进入 16KB 前 3 |
| 作品名、项目迁移 | 已正确 | 仍正确，分数拉开 |
| 某事第一次发生在什么时候 | 正确答案排第 1 | 64KB 下排第 2；16KB 下这条长记录放不进预算（Memory 已记下） |
| 我的大学在哪里 | 没有相关结果 | 带出相关但不是答案的记录；答案那条没进候选 |
