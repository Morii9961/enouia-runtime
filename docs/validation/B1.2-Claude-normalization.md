# B1.2 Claude daily-report normalization

Date: 2026-09-27. Scope: pure normalization of complete, disjoint `ccusage@20.0.20` daily JSON reports into the existing Claude Activity snapshot. Tool invocation and [Cowork store discovery](B1.2-Cowork-discovery.md) were added in later B1.2 steps. This change does not include `claude_design` usage; [ADR-019](../adr/019-claude-design-usage.md) keeps that extension behind additional gates.

Every store report must have a `daily` array and a safe `totals.totalTokens`. Each row must have a real unique `date` and safe nonnegative `inputTokens`, `cacheReadTokens`, `cacheCreationTokens`, `outputTokens`, and `totalTokens`. The first four fields must sum exactly to the row total, and all row totals must sum to the store total. `reasoningOutputTokens` is already included in output and is not added again. An empty `daily` array is accepted only with an explicit zero total; the later merge decides whether any new day is admissible. Distinct stores are summed by date with checked arithmetic, then the Activity v1 normalizer verifies the final Shanghai-labeled snapshot and strips private fields. Any invalid store fails the whole aggregate.

The [ccusage JSON guide](https://github.com/ccusage/ccusage/blob/main/docs/guide/json-output.md) describes the daily token fields and totals. A [20.0.20 issue](https://github.com/ccusage/ccusage/issues/1613) shows `period` for the **unified** `ccusage daily` command. The Runtime uses the **source-focused** `ccusage claude daily` command. A read-only check of an installed 20.0.20 package, pointed at a synthetic one-line Claude transcript in an isolated temporary config directory, emitted `date: "2026-09-25"` and the expected component/total fields for that exact invocation. The older Moriium importer also reads `date`. The parser therefore requires `date` for this source-focused mode and rejects a `period`-only row. No personal transcript was read. The Runtime-owned package still needs its own capability check before activation.

Five synthetic tests cover cache/reasoning arithmetic, cross-store dates and explicit zero, privacy projection, incomplete or mismatched reports, invalid/duplicate dates, the unified-mode `period` key, unsafe values and sums, and an empty zero store. These tests read no personal transcript or credentials.
