# B3.1 one-shot executable and integration

Date: 2026-10-01. Baseline: `c3b1bf0`. Scope: Windows `enouia-activity.exe`, explicit versioned configuration, local collector composition, locked collection/commit/send/observe/retry orchestration, and the seven planned diagnostic/migration/pause commands. No scheduled task, real receiver, authenticated collector acceptance, production migration, or desktop UI was activated.

The runner depends only on the existing independent Activity/common/Windows modules plus already pinned Serde libraries. UTC formatting reuses the contract's Gregorian conversion and round-trips exact wire timestamps, including leap/year/epoch boundaries; source calendar labels remain unchanged. Source adapters and storage rules are not replaced. Configuration uses bounded reads, rejects reparse files, unknown fields, relative paths, invalid SSH aliases/origins, and unsafe time budgets. Upload defaults off. Credential values and repository environment fallbacks are absent.

One process-owned writer lock covers recovery through the final local disposition. Existing pending is observed before retry eligibility and always blocks new collection. Manual retry bypasses wait only; no-pending retry is a no-op. A resolved old pending ends the invocation. New collection uses one shared attempt timestamp, retains failed snapshots, validates manifest publishability and failed retention, rejects batches over 4 MiB before sequence reservation, then commits immutable pending before transport. One send is the maximum. Matching public bytes and source outcomes clear pending and record evidence; SSH exit zero alone cannot do so. A disconnected send can still be resolved by public observation. Unresolved delivery persists its exact identity, retry count/time, and sanitized error. Missing transport capability returns configuration failure without clearing pending.

The cancellation port and executable's monotonic 1–900-second budget prevent a cancelled acquisition from becoming a successful committed candidate. Existing subprocess deadlines/output caps remain effective. Public polling shares a maximum 60-second budget across both HTTP fetches, with five-second spacing; the zero-wait test mode performs one bounded probe. Before-commit cancellation or clock regression reserves nothing; after a commit, interruption retains pending. The inherited fault-injection/recovery tests continue to cover the shared generation mechanism. Filesystem discovery and commits are not claimed to have hard cancellation latency or power-loss guarantees.

Nineteen new runner tests cover the shared HTTP budget; commit-before-send; successful observation and local receipt; degraded source retention; exit-zero without publication; persisted wait and automatic deferral; manual exact-byte retry; disconnect after acceptance; lost acknowledgment during wait without a send; mismatched source outcomes; pause, cancellation, corruption, delivery disabled, and invalid configuration; clock regression and cancellation after collection; no-pending retry; unavailable transport; and a synthetic 150,000-day batch rejected without truncation or sequence reservation.

Six of those tests exercise an actual copied test-build executable from a repository-external temporary directory. They import a synthetic legacy trio, diagnose paused state, resume, collect three unconfigured-source failures without network access, preserve the archive in a committed pending batch, block subsequent collection, and export the latest exact rollback trio. Other executable checks cover cross-process lock contention, corrupt-state refusal, private/relative/oversized config and duplicate-argument rejection, write-once inspection output, and per-source comparison of corrections/date gaps without selecting a seed. Private path/process sentinels are absent from exported JSON. Test roots are synthetic and removed only after explicit path containment checks.

Checks: offline `cargo fmt --all -- --check`, `cargo test --workspace` (160 tests), `cargo clippy --workspace --all-targets -- -D warnings`, `cargo build --release -p enouia-activity-runner --bin enouia-activity`, and `git diff --check` passed with Rust 1.98.1 GNU. The release executable's help entry was also exercised. The build adds no external dependency versions. No personal Activity archives, auth files, production endpoint, scheduler, Memory/Context state, or Moriium checkout was used by these checks.

Limits: port-based publication tests are synthetic observations, not acceptance by the live Moriium receiver/publisher. The copied executable checks exercise disabled delivery and unconfigured sources; they do not prove authenticated gh/Codex/ccusage compatibility, real source totals, installed tool versions, complete installer packaging, or closed-UI scheduling.
