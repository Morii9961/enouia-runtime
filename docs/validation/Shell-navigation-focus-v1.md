Several controls switch surfaces from inside the current one. These are Home's route cards (demo and connected Home), the Settings link to the Memory Vault surface, the demo provenance and activity links, and Ctrl+1–7 pressed while focus is in a surface. In each case the shell unmounted the surface that held focus. Focus fell to the document, so a keyboard user restarted from the top of the window, and the new surface was not announced. The [keyboard journey](Keyboard-journey-v1.md) used Ctrl+2/Ctrl+4 without checking where focus went afterwards.

The new 7-assertion `shell-navigation-focus` journey mounts the actual shell with its fictional demo surfaces. On the unchanged shell it passed **5/7**. Now each of those transitions focuses the labelled `main` region of the new surface (`Memory Vault content`, for example), which is already the skip link's target and adds no Tab stop. It does this only when focus was lost to the document. Rail clicks and shortcuts pressed from the rail keep rail focus, focus outside the shell is respected, and an open dialog still blocks shortcuts. The existing heading-focus routes for reviewing candidates and inspecting a capsule are unchanged.
