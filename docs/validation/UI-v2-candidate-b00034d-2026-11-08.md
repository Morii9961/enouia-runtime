## 产品修正：高对比度下导航项的键盘焦点

`contrast-only` 发现 `W05.keyboard_focus_has_separate_cue` 失败：强制颜色模式下当前页导航项的焦点框向内偏移 -4px。2026-10-06（`50a99bc`）的决定是焦点框画在元素外侧、与内侧的选中框分开；UI v2 的 `.bg-nav-item:focus-visible` 与 `quiet-runtime.css` 中更具体的 `.bg-nav-item[aria-current="page"]:focus-visible`（都是 -4px）把它压回内侧。修正只在 `@media (forced-colors: active)` 内、只对导航项把偏移恢复为 3px（两条选择器都覆盖，第一次只覆盖了较弱的那条，复测仍失败，查到更具体的规则后补上）。普通模式外观不变。截图确认焦点框画在“2 MEMORY”外侧。

## 测试脚本修正（`memory-smoke.mjs`）

`lists-only` 的三项（会话列表读取中 / 失败时不应显示“No sessions yet.”）失败于测试本身：原有拦截只按返回值形状匹配，而 UI v2 的 Sessions 页同时挂着“Workspace model calls”，它的 `operation_list` 与 `session_list` 都只返回 `{items: []}`，被拦住的是错误的请求。Tauri 2.12 的 `invoke` / `ipc` 都是冻结属性，不能包装；新增 `holdCommandObservation`：页面先暂存这段时间内所有回调结果，Node 端从网络事件的 `Tauri-Callback` 请求头认出目标命令的回调 id（只读这个头，不记录调用密钥），然后只扣住它、放行其余结果。会话列表与候选列表两处改用它。产品源码在这里本来就是对的。
