# Activity refresh and run-status error ownership

Date: 2026-10-10. Baseline: `04dc3583b6c387a730f8ba033ac6b3ee83dcbe1e`. This changes the connected React surface's error state. Activity adapter/producer, IPC, Memory pin and dependencies stay unchanged. J1/B4 remain partial; B5 is inactive.

Run-status polling and overview refresh previously wrote the same error state. Status recovery removed any error whose text matched its previous failure, including a newer failed refresh and its Retry button. A successful refresh also removed a still-unrecovered status-query error. Repeated status failures could overwrite read-retry feedback, and two distinct simultaneous errors could not both remain visible.

Run-query failure now has its own state. A successful status reply clears only that state; refresh continues to own its read failure and Retry action. Package replacement clears both contexts. Equal text is rendered once, preserving the read Retry action, while different errors remain independently visible. The existing stopped-effect guard, same-run retries, bounded backoff, terminal refresh and mutation admission remain in place.
