# R5：Sessions 合并显示跨捕获窗口的 ChatGPT 对话（2026-11-24）

Memory [ADR-MEM-185](https://github.com/Morii9961/enouia-memory)（main `4dd96b4`，#166）解决了一个问题：同一段 ChatGPT 对话持续好几天，捕获窗口一换，后面的轮次就会被拒收。现在窗口换了之后，对话会接着记成新的一段，这一段的原始对话 ID 写成 `<原 ID>#pol_…`。Memory 说明 Runtime“可以把这些段放在原 ID 下显示”。这次没有 IPC、wire 或 schema 变化，仍是 61 个命令；Memory 在 `ca76892` 之后的 ADR-MEM-176 至 188 都只改远程服务，**pin 不升**，仍为 `ca76892`。

## 改动

登记模式的 Sessions 列表里：

- 原始对话 ID 去掉 `#pol_…` 后相同的几条对话合成一行，按开始时间排，最早的一段作标题。
- 下面写“在之后的捕获窗口里接着记下：”，后面每段一个按钮，写着“第 n 段 · 开始时间 · 已捕获轮次”。
- 打开其中一段时，详情会说明这是同一段对话的第 n 段（共几段），并说明后面一段不链接到前面的轮次。

只合并当前已读入、当前筛选范围内的对话；计数仍按段计（“X 条显示 · Y 条匹配”不变）。中文、日文文案通过 CJK 字体覆盖检查。

## 边界

- 没有重新构建安装候选，也没有改原生代码。周末验收仍用 `7021984`，这项不在验收步骤里；真实库现在没有 ChatGPT 对话，接通连接器前会出新候选。
- 原 ID 太长时，Memory 会截短原 ID，让段 ID 不超过 256 个字符。这时去掉后缀后的 ID 和原 ID 对不上，各段会分开显示，不会合并。这需要原 ID 接近 256 个字符，ChatGPT 的对话 ID 远没有这么长，所以没有处理。
