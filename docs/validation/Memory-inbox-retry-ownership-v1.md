# Candidate inbox retries respect the current observation

Date: 2026-10-15 (Asia/Shanghai). Baseline `4e9cf8bd89978072634785eefe2e59b6b40c2109`; Memory pin remains `8186aed861af08cf7a2c5d8c912a24eae51b4d66`.

Ordinary inbox actions waited for a successful candidate-list observation, but the generic action error's Retry called its saved closure directly. A failed `remember` or `review_plan` request could therefore be retried during a pending list refresh or after a failed read, despite the ordinary controls being withheld. The baseline in-app-browser fixture passed 10/14, failing those two admission checks for each action.

The inbox now shares its current read/modal admission checks between ordinary actions and held retries. Retry is withheld while the list is pending, its observation has failed, another action is busy or a review dialog owns the inbox; the saved error stays visible. A fresh successful list read restores the held retry without replaying it. An invoked retry retains the original arguments and key, and completion keeps later candidate/statement/topic drafts. `remember` remains a keyed local candidate write; `review_plan` remains a keyed-null read whose result opens the ordinary confirmation dialog. This does not change Core revision checks or approve anything automatically.
