## 测试脚本修正（`memory-smoke.mjs`，产品代码未改）

八个 Vault 模式的上一份记录早于三语界面和 UI v2，本次第一次在 UI v2 上跑，全部在前几步失败。逐一定位后只改测试脚本：

1. **初始语言**：每次是新 WebView2 配置，前端跟随系统语言，这台机器是中文，而这些旅程按英文写。WebView2 启动参数加 `--lang=en-US`；三语矩阵仍通过 Settings 显式切换。
2. **大写标签**：UI v2 用 CSS `text-transform: uppercase` 显示状态徽标和小标题，`innerText` 随之变成大写，37 处等“Memory · Vault open / locked / No Vault open”的地方全部超时。新增只读徽标 `textContent` 的 `badge()`；通用 `has()` 改为 `innerText` 或 `textContent` 任一包含即可。中途试过不区分大小写，结果 `has('Evidence')` 会被列表行里的“1 evidence reference”提前满足，键盘旅程因此提前往下走并超时，已放弃该做法。
3. **页面切换**：UI v2 用 View Transition 切换页面，`nav()` 点完不等待，连续两次导航时会停在前一个页面。`nav()` 改为等目标导航按钮变成 `aria-current="page"`。
4. **过时的文案**：会话输入框的无障碍名称已改为“Ask (Send uses the local Mock…”，三处断言更新。
5. **第一次 Tab**：2026-10-17 起（`014974e`）导航后焦点会进入新页面的 main，检查里“导航后 blur”不再等于全新页面。改为重新加载页面后按第一下 Tab，跳转链接相关的检查随之全部通过。
6. **原生名称大小写**：Chromium 把 CSS 大写后的卡片标题暴露给 UIA（“MEMORY VAULT …”），该处名称比较改为不区分大小写。

## 观察到但未改的产品行为

- **快速连续导航的竞态**：两次导航间隔短于 View Transition 截取旧画面的时间（约一两帧）时，`show()` 在过渡回调真正执行前计算“当前页”，结果先点的页面会在后面生效。人手正常操作很难触发，测试脚本已改为等待。按 AGENTS.md 的原则只记录，不扩大范围；如需修复另开一片。
- 无障碍名称里的大写来自 CSS 显示效果，读屏软件可能按大写读出；未改。
