# B3.1 restricted SSH transport boundary

Date: 2026-09-28. Scope: one transport attempt for a committed Activity pending batch while the Windows writer lock remains live.

The delivery crate obtains the exact pending bytes and original sequence from the recovery-first store decision. It validates the configured absolute SSH executable and restricted alias, then uses stdin with `-T`, `BatchMode=yes`, `StrictHostKeyChecking=yes`, and `ConnectTimeout=15`. No remote command or shell text is assembled. The process has a 60-second deadline and a 64 KiB combined output cap. The pending batch must fit the receiver's 4 MiB limit. Invalid configuration, cancellation, process failure, nonzero exit, and oversized output return bounded error categories without exposing process text.

An exit code of zero returns only `TransportCompletedUnverified` with the original sequence and exact pending-byte hash. It never clears pending or claims acceptance/publication. This remains true when the receiver emits an old-sequence no-op message. The observer and acknowledgment commit are separate B3/B2 work.

Three Windows tests use synthetic locked generations and a fake process port. They verify exact stdin and arguments, old-sequence exit-zero behavior, unchanged pending state, invalid alias/cancellation/no-pending refusal, process failures, nonzero exit, and output bounds. No SSH connection or production state was used.

Checks: `cargo fmt --all -- --check`, `cargo test --workspace` (105 tests), `cargo clippy --workspace --all-targets -- -D warnings`, and `git diff --check` passed offline with installed Rust 1.98.1 GNU.
