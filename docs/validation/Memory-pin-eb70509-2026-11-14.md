## 兼容范围与最小变化

六个直接 manifest pin 与九个锁定 Memory 包指向同一 revision。固定 pin 之间 `crates/enouia-memory-workspace` 没有 diff，Workspace v1 仍为相同 61 个命令；没有修改 Runtime 适配、页面或翻译。新增 Memory 行为包括 Linux 平台层、离线分段 Morii 备份/恢复激活门、形成标题回退修正、连接器持久 `OwnerReadGrant` 及同源多范围引文。采用说明以 Memory 的 [RUNTIME.md](https://github.com/Morii9961/enouia-memory/blob/eb7050961cceaac04d4aec79257524331be6c7b0/docs/integration/RUNTIME.md) 为准。

旧评估器可能拒绝含新授权 delta 或同源多范围引文的记录；旧代码也不包含新的恢复激活门。采用兼容代码不等于自动调用这些接口：Runtime 正常模式仍使用 Workspace v1，read-1/read-2/capture 仍是显式合成入口；本片不接入正式 Morii 根，不创建授权、不调用 remote CLI 或 Provider，也没有把分段根映射成旧 Workspace 数据。

首次 `cargo fetch --locked` 报锁文件需要更新。按集成配方离线定向更新 Memory 包后，Cargo 还改动了无关包的 syn/windows-sys 解析边；已撤回这些附带变化。最终 Cargo.lock 仅修改九条 Memory source，加上新 Vault 必需的 `libc` 依赖边，没有新增 registry 包或改变其版本。随后 `cargo metadata --offline --locked` 通过。
