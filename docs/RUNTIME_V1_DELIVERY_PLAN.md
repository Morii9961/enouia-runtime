# Runtime 桌面 v1 交付清单

日期：2026-10-18。开始基线：`main@b8254d8`，Memory 固定 `56bc5eb`、workspace IPC v1 共47条命令。

Morii 要求功能逐项落实，最后统一验收，并在本轮明确选择：**先完成 Memory、对话和桌面功能；通用工具另开阶段。** 每个实现切片仍做受影响的开发验证、提交和推送；人类验收集中到冻结候选版本后。本清单不替代[架构与阶段计划](IMPLEMENTATION_PLAN_v0.3.md)，不把真实验收与生产启用提前认定为通过。

## 交付顺序

| 顺序 | 功能包 | 当前实现与下一步 | 出口 |
| --- | --- | --- | --- |
| 1 | Memory 日常闭环 | 导入、候选审核、检索、会话、检查点、实际上下文与保存恢复已有实现；本轮补充导入结果报告，历史规划仍依赖新宿主接口 | 明确哪些已可操作、哪些需要 Memory 提供接口；每个入口有可重复的开发证据 |
| 2 | Provider 使用流程 | 原生配置、凭据入口、请求审核、发送与抽取已有实现；本轮补充经核实参数的配置草稿表单 | 配置到结果恢复的完整流程；真实调用另在统一验收验证 |
| 3 | Runtime 状态与 Windows 收尾 | 本轮原生 Inspector 已接入真实状态并完成开发验证；托盘、自启动与安装器已有实现 | Inspector 使用各自后端的只读状态，失败保持未知；安装与系统交互列入验收 |
| 4 | Activity 收尾 | J1/B4 部分完成，B5 未激活 | 对照既有矩阵补实现或演练缺口；生产切换留在验收后的单独启用步骤 |
| 5 | 冻结与统一验收 | 尚未开始 | 记录固定版本、验证结果和未关闭问题；Morii 集中验收后处理受影响项 |

功能清单以用户任务完成为出口，不靠增加局部修正或测试数量判断完成。模型直接调用文件、命令行等通用工具不进入本轮桌面 v1，后续另定种类、执行权限和验收范围；现有 Activity 工具和 Memory MCP 规划不能作为其完成证据。

## 历史能力的接入依赖

[Memory 固定版本报告](validation/Memory-pin-56bc5eb-2026-10-17.md)说明历史规划、批次材料化、跨时间比较、主题回顾、语义提案与质量评审为可选原生 helpers，Runtime 尚未采用。核对固定版本的 `runtime-surface.json`、workspace `lib.rs` 与 `native.rs`：47条页面命令没有历史规划或这些 helpers 的入口；它们也没有作为 Workspace 的公开宿主方法开放。

因此，更新 pin 不会自动开放历史功能。下一项跨仓库工作应在 **Enouia Memory** 增加受其阶段约束的宿主入口：绑定已归档原件和来源修订、返回有界规划/覆盖/缺口、限定调用面、跟随 Vault 生命周期并保留删除与来源规则；相应契约与兼容记录由 Memory 负责。Runtime 随后采用固定修订，展示与选择批次，逐项接入后续操作。

Runtime 不自行读取 Vault 文件、重建解析规则、调用未公开内核状态或增加本地分叉。该依赖待 Memory 交付；本轮继续可独立完成的 Runtime 项目。

## 首个切片：原生 Inspector 的真实状态

- Memory 复用共享的 `workspace_status` 观察，展示组件、Vault、操作数与待审数；不显示 Core 中固定的 Activity 行。
- Windows 外壳使用只读 `shell_status`；Activity 分别使用自身 `activity_setup(status)` 与 `activity_get_overview`。
- 每个部分独立显示等待、错误和重新读取。外壳/Activity 标明最后读取时间；不因传输成功宣称已发布，不因任务已注册宣称定时执行成功。
- 浏览器仍保留明确的虚构演示；Inspector 不提供写入、模型请求、采集、调度开关或部署操作。
- 此切片的实现和开发验证见[Inspector 报告](validation/Runtime-inspector-v1.md)；人类验收仍待统一进行。

## 集中验收清单

导入结果的只读查看切片见[报告](validation/Import-report-v1.md)：显示已接收输入的处理计数和缺口，不将归档或解析完成视为完整历史、提炼质量或记忆审核通过。

1. 选定资料的导入、提炼、审核、纠正/删除、会话使用和重启续接；区分原始档案、待审候选和正式记忆。
2. 选定 Provider 的凭据、HTTPS、请求审核、实际回答/提取及失败恢复；真实语义质量由人评审。
3. Windows 登录启动、物理托盘与快捷键、Narrator/对比主题、存储失败恢复、安装升级和分发要求。签名是否阻止个人试用需明确，不能用未签名包宣称完成签名。
4. Activity 独立链路与恢复，按既有 J1/B4 矩阵签收；B5 另按迁移手册启用，分别记录采集、上传、发布、页面和真实调度。

真实账户、个人 Vault、历史外发及生产启用仍需要对应的明确授权。最终目标继续是云端 Memory 单主、Runtime 管理、受限 MCP 接入与本地离线/备份恢复；Host/MCP、云端和副本由 Memory 后续阶段交付，不将其写作本地桌面已实现能力。
