# 发散协议

目标：做出**真正不同**的几个方向，而不是同一个设计换五次颜色。这一份规定怎么想、怎么选、怎么隔离、怎么呈现。

## 1. 概念先行

每个方向先写一句话的世界观，形式固定：

> 这不是一个后台，这是一张 ______ / 一间 ______ / 一份 ______。

好的概念是一个**有自己的字体、材质、排版规矩的实物或场所**：潮汐表、暗房、车站发车板、行打印纸、美术馆展签。坏的概念是形容词（「现代而温暖的」）或风格名（「极简」「玻璃拟态」）。

概念之后，所有决定都要能回答「这符合它吗」：

- 它的**结构**长什么样？（实物是怎么排信息的）
- 它的**字**是什么样的？（实物上印的是什么字）
- 它的**颜色**从哪来？（实物的材料和油墨）
- 它的**材质**是什么？（纸、墨、荧光屏、胶片、金属丝印）
- 它的**声音**是什么？（实物上的文字怎么说话）
- 它**怎么动**？（机械步进、液体缓动、翻板、显影）

## 2. 想概念的方法

1. 先写 8 个概念。来源：`directions.md` 的方向库、「实物清单」，或你自己想的。
2. **划掉最先想到的 3 个。** 最先想到的通常就是最大概率的那几个，也就是别人也会得到的。
3. 从剩下的里面选 N 个（默认 5）。
4. 至少 2 个来自方向库之外，从实物清单里或你自己发明。

## 3. 六轴与距离规则

给每个方向在六个轴上各填一个具体取值：

| 轴 | 例子 |
| --- | --- |
| A 世界观 | 暗房 / 海图 / 车站 / 行打印纸 / 展签…… |
| B 结构骨架 | 侧栏+主区 / 单栏长卷 / 可平移画布 / 行表 / 径向 / 桌面窗口 / 横向走廊 / 时间主轴 |
| C 密度与节奏 | 极稀（一屏一事）/ 中 / 极密；均匀 / 忽大忽小 |
| D 字的声线 | 高反差衬线 / 等宽 / 窄体工业 / 宽体无衬线 / 点阵 / 手写批注 / 中文衬线主导 |
| E 色彩世界 | 近黑+一个暖色 / 单一蓝 / 两色叠印 / 近无彩+一张图 / 全彩但有限 / 点阵单色 |
| F 动的性格 | 几乎不动 / 机械步进 / 缓慢显影 / 翻板 / 液体 / 可拖拽的物理感 |

**距离规则：**

- 任意两个方向，在 B、C、D、E、F 里至少有 **4 个**不同；A 必然不同。
- 展示字体不能是同一个字体族。
- 强调色不能在同一色相区间（相差至少 60°）。
- 不能有两个方向共用同一个结构骨架。
- 把表填进 `.design/01-directions.md`，一眼可查。

**范围规则：**

- 至少 1 个**安静**的（密度低或色彩极少）。
- 至少 1 个**大胆**的（会让人说「哇」）。
- 至少 1 个**古怪**的（你不确定用户会不会喜欢，但值得一试）。
- 一个方向可以同时占两种。

## 4. 方向库是种子，不是模板

用库里的方向时，必须**至少改掉 3 处具体的东西**（换一个色相、换一个字体、换一个结构元素），并且在 `DIRECTION.md` 里写出改了什么、为什么。原样复制库里的方向视为没有设计。

## 5. 每个方向的 DIRECTION.md

一页，全部是具体值。

```
# <序号>-<名字>

概念（一句话）：
它不是：
六轴：A… B… C… D… E… F…
色板：角色 → hex（6 个以内，含一个强调色）
字体：展示/正文/数据/中文标题/中文正文 → 字体名（授权已核实）
字号阶梯：…
间距单位与圆角：…
材质与线条：…
布局骨架（一小段话或 ASCII 草图）：
招牌时刻（只一个）：
动效性格：…（时长、缓动）
数据可视语言：图表怎么画、怎么标注
文案声线：三句示例
三个「通用模板不会做」的决定：
这个方向的风险（它可能哪里让人不喜欢）：
与库的距离：用了哪个种子？改了哪三处？
```

## 6. 切片：每个方向做什么

不是整站，是**垂直切片**，足够判断好不好看：

1. 总览页（最能体现概念的一屏，含招牌时刻）。
2. 最密的一个数据页（最考验字体、对齐、图表）。
3. 一个边缘状态：空 / 加载 / 错误 之一，用概念的声线。
4. 手机宽度（390）下前两者的样子，**重新组织**，不是缩小。

全部使用同一份真实数据（`.design/fixtures/`），这样方向之间的差异只来自设计。

## 7. 并行与隔离

- 每个方向自己的目录（例如 `.design/variants/03-nautical/`）或路由（`/__design/03-nautical`）、自己的 CSS、自己的字体声明。**共享的只有 fixtures。**
- 在独立分支上做，不碰现有前端。
- 用子代理并行时：一个方向一个子代理；告诉它读哪几份文件和它那份 `DIRECTION.md`，让它**自己读**；明确它只能写自己的目录。主代理负责距离检查和最终汇总。
- 先写完所有 `DIRECTION.md` 再动手实现，避免做着做着趋同。
- 实现中途如果发现两个方向开始看起来像，立刻回头改其中一个的 B 或 E 轴。

## 8. 呈现与停下

`.design/review/index.html`（由 `tools/shot.mjs` 生成并排截图），每个方向一张卡：

- 概念一句话。
- 三档宽度的截图。
- 「它赌了什么」：招牌时刻和最大胆的一个决定。
- 「它的短板」：诚实写。实在写不出就说明你还没认真看。
- 本方向自检做了几轮、最后修掉了什么。

最后给出你的**倾向**（可以有，不要超过三句），但**不要替人选，也不要继续往下做**。停下，等人回复。

## 9. 收敛

人选定后：

- 可以混搭（「A 的字体 + C 的结构」）。混搭后必须重新过一次 `critique.md`，因为混搭常常变丑。
- 写 `DESIGN.md`（每个字段具体值），并在 `docs/design-decisions.md` 记第一条：选了什么、放弃了什么、为什么。
- 然后才做完整实现，实现期间不再发散；新问题回 `DESIGN.md` 找答案，找不到就补一条决定。
