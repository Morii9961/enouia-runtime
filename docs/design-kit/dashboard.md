# 后台 / 看板的设计要点

后台最容易被做成同一个样子：侧栏 + 四个 KPI 卡 + 一张折线图 + 一张表。这一份是为了让「信息密集」和「有设计」同时成立。无论选哪种风格都适用。

## 1. 数字是主角

- 一页里先决定**哪个数字是主角**，把它做大到有招牌感，其余往下排。四个等大的指标卡是「没有决定」。
- 数字旁边必须有**单位**和**时间范围**。离开它们的数字没有意义。
- 数字用等宽数字（`tabular-nums`）或等宽字体，变化时对齐不跳动。
- 趋势不是装饰：一个箭头和「+12.5%」不算信息，说清楚是和什么比的。

## 2. 图表就是这个方向的性格

默认图表库的外观是 slop 最大的单一来源。每个方向的图表语言要从概念里长出来：

- 暗房：数据作为曝光值，条形像一格格底片。
- 海图：数值是测深数字，趋势是潮汐曲线。
- 行打印纸：块字符画（▁▂▃▅▇）。
- 孔版：网点填充与叠印。
- 展签：几乎没有图表，一个巨大的数字加一条细线。

做法：

- 用手写 SVG、`d3-shape` / `d3-scale`、`uPlot` 这类可控度高的方案，不用开箱即用的 Recharts / Chart.js 外观。
- 直接标注：把数值和说明标在线上或点旁边，坐标轴减到最少，图例能不要就不要。
- 每张图一个结论，图标题就写这个结论，不写「访问量趋势」。
- 分类色 ≤ 4；要靠颜色区分时，再加形状、线型或标签，颜色不是唯一线索。
- 提供表格视图作为文字替代（可以藏在一个次要的切换后面）。

## 3. 状态覆盖

每个方向至少做出这些状态，并用概念的声线：

- **加载**：不是转圈。暗房 = 显影，蓝晒 = 曝光，行打印 = 逐行打印。
- **空**：不是空盒子加一句「暂无数据」。给出下一步，并带一点声线。
- **错误**：说发生了什么，再说可以做什么。
- **过期 / 离线**：数据旧了要看得出来。

## 4. 信息架构不变，外观可变

- 功能清单是约束：不删功能，不改接口，不改数据含义。
- 允许改变的是：布局骨架、导航形式、控件长相、信息的分组方式。
- 导航不一定是侧栏。可以是索引、时间轴、画布上的位置、抽屉。
- 控件（筛选器、时间范围、开关）按概念自制，不用浏览器默认外观；但键盘可达，焦点环要风格化而不是去掉。

## 5. 响应式

手机不是把桌面缩小：

- 至少 1440 / 820 / 390 三档，每档重新组织。
- 手机上优先主角数字和最常用的操作；次要信息折进可展开的区域，不要做横向滚动的表格作为默认。
- 触控目标 ≥ 44px。

## 6. 明暗模式

- 不强制双模式。概念决定：暗房只能是暗的，展签只能是亮的。
- 只做一种时，在 `DESIGN.md` 写明理由，并确保那一种满足对比度。
- 做两种时，两种单独选色，深色不是浅色的反转。

## 7. 性能与无障碍的底线

- 字体预算见 `type-cjk.md`。
- 图片响应式交付，保持尺寸稳定。
- 键盘可达、焦点可见、`prefers-reduced-motion` 有对应处理。
- 动效有目的：去掉它如果什么都没变，它就不该存在。机械步进、翻板、显影这类，是**概念**，不是装饰。

## 8. 微文案

声线跟随概念，三处必写：主要按钮、空状态、错误提示。例子：

- 暗房：「显影中……」「这个月还没有曝光」「定影失败，药液可能过期了」
- 海图：「测深中」「这片海域暂无记录」「信号丢失，仍显示昨日潮位」
- 行打印：「PRINTING…」「NO RECORDS FOUND」「*** PAPER JAM ***」

中文界面用中文声线，不要硬译英文梗。
