# 改造已有应用的设计

适用：项目已经有设计规范、组件、测试，甚至有一份「已冻结」的设计，这一次要做的是**重新设计视觉和布局**，不是从零开始，也不是给旧设计换个颜色。桌面应用（Tauri / Electron）尤其适用。

## 1. 先分清契约和皮肤

| | 契约（不变） | 皮肤（可变） |
| --- | --- | --- |
| 内容 | 功能清单；行为规范（交互、门控、撤销、安全语义）；数据和 IPC；文案的含义；i18n 的键；无障碍底线；CSP 与资源限制；已有测试 | token（色、字、间距、圆角）；字体；组件外观；布局骨架；导航形式；动效；图标；文案的声线（含义不变） |

阶段 0 的 `00-recon.md` 里加两栏：

- **契约清单**：旧设计文档里哪些条文其实是行为或安全语义（例如「没有 Preview 就不能写入」「红色代表失败并说明文件安全」「颜色之外还要有符号和文字」）。这些**语义**必须保留。
- **皮肤清单**：哪些条文只是审美决定（例如「22px 行高」「深色」「单一强调色」「不要卡片」）。这些可以被新设计取代。

保留语义，不保留具体长相：「红色代表失败」可以继续，但那个红是什么红、是红字还是红印章、是色块还是下划线，都是皮肤。

## 2. 旧设计文档的处理

- 不要直接修改「已冻结」的文档。
- 人选定方向之后，在项目的决定记录里写一条：新设计取代了哪份旧设计的哪些条文、哪些条文保留。
- 然后只在旧文档**顶部加一行**「已被某某决定取代」，不改正文。
- 旧设计里已经评审过、被否决的做法，要先读一遍，别重复踩。

## 3. 变体用 git worktree

应用有构建、依赖和测试，变体不适合放在 `.design/variants/` 的一个文件夹里。

- 每个方向一个 worktree、一个分支：`git worktree add ../<项目>-wt/<序号>-<名字> -b redesign/<序号>-<名字>`。
- 每个 worktree 里自己 `npm ci`，自己的开发服务器端口（例如 1431、1432……，避开项目默认端口）。
- 子代理只在自己的 worktree 里写。主工作区保持干净，不放任何方向的改动。
- 不要自动删除 worktree 和分支，清理等人确认。

## 4. 用项目自带的 mock / 预览模式出图

- 先找项目有没有「浏览器预览 + mock 后端」（常见：`npm run dev`）。有就用它截图，不需要原生壳，也不需要真实数据。
- 缺的状态（大量数据、超长文件名、中文、错误、空）扩展 **mock**，不要碰后端。
- 原生窗口的特有部分（托盘、悬浮窗、原生菜单）能在浏览器里渲染就渲染，渲染不了就用最小的测试页单独验证，并在报告里写明验证的是什么。
- 照片、真实个人数据、密钥不进截图、不进仓库。

## 5. 视口

桌面应用不做手机宽度，除非它本来就有。用应用的**最小窗口宽度**作为最小一档：

```bash
node tools/shot.mjs --out shots --widths 1100,1440,1920 --height 900 name=url
```

按项目配置的最小窗口（例如 1100×640）再单独截一张，确认最小窗口下不破。

## 6. 切片

切片 = 真实页面里的几个状态：

1. 最能代表这个应用的一屏。
2. 最密的数据页。
3. 一个边缘状态（空 / 加载 / 错误 / 恢复）。
4. 最小窗口下前两者的样子。
5. 项目里有别的独立窗口（悬浮窗、对话框）时，其中最有代表性的一个。

## 7. 测试与检查是契约的一部分

- 开始前先跑一遍项目的构建、测试和检查，记下基线（哪些是通过的，哪些本来就失败）。
- 每个方向交付前，项目自己的检查必须和基线一样通过。失败不是「设计的代价」，要修。
- 如果测试断言了旧设计的细节（固定的 class 名、像素高度、颜色值），记录下来，改测试时说明理由，**不要为了让测试通过而保留旧样式**，也不要悄悄删测试。
- 布局常量（虚拟列表的行高、固定的栏宽）与组件要同步修改，并更新对应的测试。
- 新增的字体和依赖：核实授权，按项目的流程更新第三方声明，评估对安装包体积的影响，自托管。

## 8. 发现契约有问题怎么办

不要为了让设计成立去改行为。把发现记进 `.design/spec-issues.md`（哪一条、为什么有问题、你的建议），继续做，最后一并告诉人。

## 9. Git 习惯

- 全程只在本地分支提交，**不推送、不开 PR、不合并**，除非人明确说。
- 遵守项目自己的提交规则（例如签名、提交信息的尾注）。
- 设计工具包装进项目的那些文件，只放在探索分支上；是否并入主线，等人决定。
