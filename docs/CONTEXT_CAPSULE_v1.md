# Inspectable Context Capsule v1

Date: 2026-10-01. Authority: Architecture v0.3 §6 and ADR-007. Scope: A1 contract follow-up and A2 pure ranked-capsule assembly. Filesystem/FTS retrieval, Provider orchestration and UI remain pending.

[Capsule v1](../contracts/context/capsule-v1.schema.json) retains all architecture fields: capsule ID/time/query, Identity, user and relationship context, active projects, relevant memories, recent checkpoints/turns, open loops, provenance and `budget.max_tokens`. Capsule IDs use `cap_` plus 32 lowercase hex digits. Canonical record fields remain unchanged. Selected memories must be active, no later than capsule generation, and exactly equal to records in the validated Memory/Session bundle. Selected turns must match the original session/turn/role/content/source/time. Candidate proposals and Activity data have no capsule field or lookup path.

Each selected Identity, memory and turn has exactly one provenance entry with its section reason and source ID where applicable. Duplicate IDs, missing/extra provenance and changed canonical content fail. Top-level open loops derive from included active projects and checkpoints in section order, with repeated identical strings removed; callers cannot add extra hidden instructions there. The initial Identity allowlist is `core.md` and `runtime_rules.md`. This model checks supplied Identity shape, not actual file ownership; the future Vault adapter must read the authorized files.

The local `utf8_bytes_v1` policy counts one estimated token per byte of the complete compact UTF-8 serialized capsule, plus 256 units of framing reserve. This includes metadata, escaping, provenance and the budget fields themselves. Estimation reaches a fixed point for the estimate's own decimal representation. It is a deliberately conservative local sizing rule for the Mock slice, not a verified tokenizer bound for an external model. A real Provider must separately enforce its own token limit and framing contract before invocation.

Mandatory base fields (including query and supplied Identity/turns) must fit, otherwise compilation refuses explicitly. A retrieval port supplies ranked canonical memory IDs; lower rank comes first, equal rank breaks by memory ID. Input order does not change equal-rank results. Conflicting classifications for the same ID are rejected. Inactive and duplicate records get explicit exclusion reasons. Optional memories are admitted whole with their provenance/derived open loops; a record that exceeds the budget is excluded intact and later smaller records may still fit. No string, date range, project state or Identity is silently truncated.

`compile_ranked` returns the actual capsule plus exclusions. `provider_bytes` revalidates it against the complete canonical bundle and serializes that exact capsule, without additional hidden context. It performs no Provider call or snapshot persistence. FTS/query scoring and evidence for unrelated-memory exclusion still belong to the retrieval adapter. The current provenance reason describes the chosen section; richer match explanations remain part of the FTS adapter/inspector follow-up.

The synthetic [frozen capsule](../tests/fixtures/context/capsule-v1.json) includes one ProjectState and one checkpoint and estimates exactly 2,427 units (2,171 compact UTF-8 bytes plus reserve). Its selected source records and raw turns live in the separate synthetic continuity fixture. JSON round trips and byte-budget checks establish model behavior, not persistent Inspector state or a measured 300 ms retrieval target.
